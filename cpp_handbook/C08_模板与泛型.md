# C08 模板与泛型 【进阶】

> 模板 = "编译期生成代码的模具"。CUDA 里的 kernel 模板、CUB/Thrust、Eigen 全靠它。

## §C08.1 函数模板

**作用**：写一份逻辑，编译器按用到的类型**各自生成一份**代码。

```cpp
template <class T>              // T 是占位类型, 调用时由编译器推导
T maxOf(T a, T b) { return a > b ? a : b; }

maxOf(3, 5);        // 编译器生成 int 版
maxOf(1.5, 2.5);    // 编译器生成 double 版 —— 两份不同的机器码
maxOf<int>(3, 5.2); // 显式指定 T=int (5.2 被转成 5)
```

【机制】模板不是"运行时万能"，是**编译期按需实例化**——每个用到的类型都生成一份专门代码。
这也解释了"模板为什么必须放头文件"（前置：T3-32）。

### §C08.1.1 `class` vs `typename`：**完全等价，纯风格差异**

`template <class T>` 和 `template <typename T>` 在这里**一个字的意思差别都没有**，
换着写、混着写都行（实测）——包括参数包 `template <typename... Args>` 也完全合法
（`class... Args` 同样合法，你在 C07 §C07.6 见过的那种）。

```cpp
template <class T>    T one(T x) { return x; }   // class 版
template <typename T> T two(T x) { return x; }   // typename 版 —— 一模一样
```

**那为什么两种写法并存？** 历史原因：C++ 早期只有 `class`；`typename` 是后来加的
（在别的场景它有独立含义：依赖类型前缀，如 `typename T::value_type`）。**风格建议**：
现代代码多用 `typename`（读起来是"某个类型"，不像"class"会误导人以为只能是类）。
【冷知识，看不懂可跳】C++17 之前有个边角：模板的模板参数里只能写 `class`
（`template<template<class> class C>`），C++17 起这个限制也取消了。

## §C08.2 类模板

**作用**：泛型容器/数据结构。

```cpp
template <class T>
class Box {
public:
    explicit Box(T v) : v_(v) {}      // explicit(第 27 题)
    T get() const { return v_; }
private:
    T v_;
};
Box<int> a(1);          // 实例化 Box<int>
Box<double> b(2.5);     // 这是另一个完全独立的类型!
// a = b;               // ✗ Box<int> 和 Box<double> 互不相干
```

【CUDA 相关】你的第一个 kernel 模板：`template<int BLOCK> __global__ void k(...)`——
BLOCK=128/256 各生成一份（G09 速查有实例）。

## §C08.3 模板参数可以是"值"

**作用**：把常数编进类型，编译期确定。

```cpp
template <int N>
struct Array {
    int data[N];                       // N 必须编译期已知
    constexpr int size() const { return N; }
};
Array<256> a;      // 256 个元素, 编译期定死
```

## §C08.4 特化：给特定类型"开小灶"

**作用**：某类型的实现和通用版不同时，单独写一份。先逐字拆原例的语法（新手第一眼全懵的那种）：

```cpp
template <class T>                     // ← 函数模板的"模板头"
const char* typeName() {               // ← const char* = 返回值类型(一个C字符串);
    return "unknown";                  //    typeName = 函数名; () 里没参数!
}                                      // T 没出现在参数里 → 调用时必须显式写 typeName<int>()

template <>                            // ← 全特化的记号: 尖括号【空着】= "T 即将定死"
const char* typeName<bool>() {         // ← typeName<bool>: 上面那行的 T=bool 专属版
    return "bool";                     //    以后调 typeName<bool>() 走这份, 其他类型走通用版
}

typeName<int>();      // "unknown"  ← 用通用版
typeName<bool>();     // "bool"     ← 自动命中专属版(编译期就定好, 零运行时开销)
```

**为什么这么写有好处（动机实例，CUDA 真场景）**——不同类型要用不同的对齐/指令/常数：

```cpp
template <class T>  int alignOf() { return 4; }    // 通用: float/int 给 4 字节
template <>         int alignOf<__half>() { return 2; }  // half 专属: 2 字节(实测同理)
// 调用方完全无感: alignOf<T>() 一行, 编译器自动挑对版本 —— 没有虚函数、没有 if、零开销
```

这就是**编译期的"if-else"**：`if (T==bool)` 的分支选择在编译期完成。生产代码里的
`std::hash<你的类型>`（给 unordered_map 用）就是这么特化的；CUTLASS 里 half/float
各走各的乘加指令也是这套。【注意】特化**必须已经存在通用版**（先有模板才能开小灶），
且两份的**函数签名必须完全一致**（只换实现，不换接口）。

### §C08.4.1 通用版/特化版什么时候定类型 + `typeName<bool>()` vs `typeName(bool)`（高频混淆）

**通用版和特化版都是编译期定类型的，区别是"模具 vs 现成品"**：

- `template <class T>` 通用版 = **模具**：T 是占位坑，**没人调用就一行代码都不生成**；
  谁调用 `typeName<int>()`，编译器才当场按模具压一份 int 版出来（仍然在编译期）。
- `template <> typeName<bool>()` = **给 bool 手写的现成品**：调用 `typeName<bool>()` 时
  编译器直接拿这份，不再从通用模具压。也是编译期。

**`typeName<bool>()` 和 `typeName(bool b)` 是两个宇宙的东西**——尖括号给**类型**，圆括号给**值**：

| | `typeName<bool>()`（模板）| `typeName(bool b)`（普通函数）|
|---|---|---|
| `<bool>` / `(bool b)` 是 | **模板实参 = 类型** | **函数形参 = 值** |
| 分流/分支时机 | **编译期**就选好哪个版本 | **运行期**才看 b 是 true/false |
| 调用时给什么 | 什么数据都不给（圆括号空着），只"报类型" | 必须交一个 bool **值** |
| 能收运行期的东西吗 | ✗ 尖括号里只能放类型（编译期必须已知）| ✓ 值可以是运行期才算出来的 |

实测（一行看懂）：

```cpp
typeName<bool>();            // ✓ 报的是"类型", 不传任何数据
byValue(true);               // ✓ 交一个值
bool flag = (getchar()=='y');// 运行期等用户按键才知道的值
byValue(flag);               // ✓ 普通函数能收
typeName<flag>();            // ✗ error: type/value mismatch —— 尖括号要"类型", 值塞不进去
```

**人话版**：模板是"**按类型**开小灶"（float 走 float 的灶、half 走 half 的灶，灶在编译期
就分好，两个灶是两份独立代码）；普通函数带 bool 参数是"**按值**走分支"（一个函数里
`if (b)` 两份代码都编进去，运行期再选）。**类型编译期就已知，值往往运行期才知道**——
这就是两条路各自的存在意义。

**记忆钩子**："**尖括号装类型（编译期），圆括号装值（运行期）；类型开灶，值走分支。**"

## §C08.5 CRTP：编译期多态 【进阶，CUDA 高频】

**作用**：不用 virtual 实现"基类调派生类的方法"——零开销、可内联（第 01 题性能实验主角）。

**先回答"这哪里多态了"**：多态的定义是"**同一个调用点，不同类型有不同行为**"——
`f.run()` 和 `s.run()` 是同一段代码，跑出来行为不同，这就是多态。区别只在**分流时机**：

| | virtual（C05.3 的运行期多态）| CRTP（编译期多态）|
|---|---|---|
| 谁是哪个实现 | **运行期**查 vtable 决定 | **编译期**由模板参数 D 定死 |
| 开销 | vptr/vtable + 间接跳转, 难内联 | 零: 编译后就是普通直接调用, 可内联 |
| 灵活性 | 同一指针可指向任意派生类(运行才知) | 类型必须编译期已知 |

所以**多态 ≠ 必须 virtual**——virtual 只是"运行期"那一种。逐行拆：

```cpp
template <class D>                         // D = "将来要继承我的派生类"(把自己传进来)
struct Base {
    void run() {
        static_cast<D*>(this)->run_impl(); // ①this 原是 Base<D>*; ②转成 D*;
    }                                      // ③立刻调 D 的 run_impl —— 你读对了!
};                                         // 为什么敢转: Fast IS-A Base<Fast>(它真继承着),
                                           // 对象本体就是 Fast, 向下转安全
struct Fast : Base<Fast> {                 // 派生类把"自己"当模板参数传给基类(CRTP 名字由来:
    void run_impl() { printf("fast!\n"); } //   Curiously Recurring Template Pattern 奇异递归)
};
struct Slow : Base<Slow> {
    void run_impl() { printf("slow\n"); }  // 没有 virtual! 也没有 override!
};
Fast f; Slow s;
f.run();   // "fast!"  ← 同一个调用点 run()
s.run();   // "slow"   ← Base<Fast> 和 Base<Slow> 是两个不同模板实例,
           //            各自的 run() 在编译期就绑死了各自的 run_impl —— 这就是编译期多态
```

【CUDA 相关】CUB/Thrust 的 functor、你 hgemm 里 `template<int kStages>` 的多级流水全是这套。

## §C08.6 functor（仿函数）：能像函数一样用的对象

**作用**：重载了 `operator()` 的类对象——比函数指针强：可以带状态、可内联。

**先澄清一个误会：仿函数和 explicit 毫无关系！** 仿函数的**唯一身份证是
`operator()`（函数调用运算符的重载）**。原文例子里的 `explicit` 长在**构造函数**上，
防的是 `float` 偷偷变 `Scale`（C05 §C05.2.3），纯属两件事恰好出现在同一个 struct 里。

```cpp
struct Scale {
    float k;
    explicit Scale(float k) : k(k) {}          // ← 这是普通构造函数的 explicit(与仿函数无关)
    float operator()(float x) const {          // ← 【仿函数的身份证】重载 operator():
        return x * k;                          //    有它, 对象就能"像函数一样被调用"
    }
};
Scale s(2.0f);
printf("%f\n", s(3.0f));    // 6 —— s(x) 实际是 s.operator()(x)
```

**"只能在结构体或类里用是吗"**：`operator()` 必须是**类的成员函数**（不能是全局函数），
所以是的——仿函数必须住在 struct/class 里。但注意 **lambda 就是编译器自动生成的
匿名类 + operator()**（C02 §C07 学过捕获），所以你写 lambda 时其实一直在"用类"。

```cpp
// 配合模板: kernel 里的元素级操作(K 是模板参数 → operator() 内联进 kernel)
template <class F>
float apply(F f, float x) { return f(x); }
apply(Scale(3.0f), 5.0f);              // 15
apply([](float x){ return x + 1; }, 5.0f);   // lambda 也是 functor(编译器生成的匿名类)
```

【CUDA 相关】`thrust::transform(begin, end, out, functor)` 就是把 functor 内联进 kernel——
这是 X03 的主角。
