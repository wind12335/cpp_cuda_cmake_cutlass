# C04 标准库容器与常用算法 【核心】

> C++ 标准库（STL）把最常用的数据结构都做好了——**不要手写链表/哈希表**，先学会用。

## §C04.1 std::string：字符串

**作用**：自动管理内存的字符串，拼接/查找/子串都是成员函数。

```cpp
#include <string>
std::string s = "hello";
s += " world";                  // 拼接
size_t n = s.size();            // 长度 (不含隐藏的 '\0')
std::string sub = s.substr(0, 5);   // "hello"
if (s.find("world") != std::string::npos) { /* 找到了, npos=找不到时的特殊值 */ }
printf("%s\n", s.c_str());      // 传给 C 接口(如 printf)时转成 C 字符串
```

【前置：C03 §5】string 自己管理堆内存，深拷贝自动正确（面试第 17 题 Rule of Zero 的样板）。

## §C04.2 std::vector：动态数组（最重要的容器）

**作用**：可自动扩容的数组，连续内存、随机访问 O(1)、尾部增删均摊 O(1)。

```cpp
#include <vector>
std::vector<int> v;             // 空
v.push_back(3);                 // 尾部加元素
v.emplace_back(4);              // 同上(对 int 来说两者完全等价, 见下方辨析)
std::vector<int> w(100, 0);     // 100 个 0
std::vector<float> f(1024);     // 1024 个 float —— CUDA host 缓冲的常用姿势
f[0] = 1.0f;                    // 随机访问 O(1), 不检查越界(越界=未定义行为)
f.at(5) = 2.0f;                 // at() 会检查越界并抛异常(慢一点但安全)
for (size_t i = 0; i < f.size(); ++i) { /* ... */ }
```

### §C04.2.1 push_back vs emplace_back 辨析（面试第 12 题）

**人话版**：push_back 是"**先在别处把东西做好，再搬进容器**"；emplace_back 是"**把原料直接送进容器里头现场做**"（emplace = 就地放置）。

- `push_back(对象)`：你给它一个**现成的对象**，它把这个对象**拷贝/移动**一份放进容器尾部。
- `emplace_back(构造参数1, 构造参数2, ...)`：你给它**造对象的原料**（构造函数的参数），它**在容器尾部原地调用构造函数**——省掉了临时对象和一次搬运。

```cpp
// 装 int 这种"裸值"时: 两者毫无区别(int 没有构造过程可言)
v.push_back(3);
v.emplace_back(4);        // 干的事一模一样

// 装 pair/string 这种"有构造过程的对象"时: 区别才显现
std::vector<std::pair<std::string, int>> vp;

vp.push_back(std::make_pair("gpu", 8));
// 过程: make_pair 先在旁边造好一个临时 pair("gpu",8)
//      → push_back 把这个临时对象【拷贝】进 vp → 临时对象销毁
// (共: 一次构造 + 一次拷贝 + 一次析构, 字符串"gpu"被复制了两份)

vp.emplace_back("gpu", 8);
// 过程: 把 ("gpu", 8) 两样原料直接送进 vp 尾部, 【原地】构造出 pair
// (共: 一次构造, 省掉了临时对象和拷贝)
```

**记忆钩子**：push_back 收"**成品**"，emplace_back 收"**零件**"。给成品它也得拆开重装？不——它直接搬；给零件它现场装。

**实用建议**：知道元素类型时**优先写 emplace_back**，不亏；面试被追问再讲上面的"临时对象+拷贝"过程。性能差异在 string/大对象、循环里插入上万次时才可感（一次 string 拷贝就是一次堆分配）。

【前置：C02.6 移动语义】C++11 后 push_back(临时对象) 会走**移动**而非拷贝（省大半），所以现代代码里两者差距缩小了——面试能讲到这层就是加分项。

【前置：T1-11 vector 扩容机制】reserve/resize/迭代器失效——面试高频，务必回看。

## §C04.3 map / unordered_map：键值对

**作用**：按 key 存取 value。map=红黑树有序；unordered_map=哈希表更快（面试第 13 题）。

```cpp
#include <map>
#include <unordered_map>
std::unordered_map<std::string, int> ages;
ages["alice"] = 30;                     // 插入或覆盖
int a = ages["alice"];                  // 取
if (ages.count("bob")) { /* 存在才用 */ } // 查存在性(用 [] 查不存在的会插入默认值! 这是坑)
for (auto& [key, val] : ages)           // C++17 结构化绑定遍历
    printf("%s -> %d\n", key.c_str(), val);
```

### §C04.3.1 `for (auto& [key, val] : ages)` 拆开看（结构化绑定）

这行看不懂很正常——它是**三件事叠在一行**里。拆开：

**第一层：map 里装的到底是什么？**
`map<string, int>` 里每个元素是**一个 `std::pair<std::string, int>`**——一个"钥匙-值"对的小盒子：

```
ages 的内存形象:  [ ("alice", 30), ("bob", 25), ... ]
                    ↑ 每一格都是一个 pair
```

**第二层：range-for 每圈取出什么？**
`for (auto& X : ages)` 每循环一圈，X 就是**其中一个 pair 盒子**。不用结构化绑定的老写法（C++11/14 时代，老代码里到处是）：

```cpp
for (auto& p : ages)                    // p 是一个 pair<string,int>
    printf("%s -> %d\n", p.first.c_str(), p.second);
//                            ↑first=盒子里的第一样(key)  ↑second=第二样(value)
```

**第三层：`[key, val]` 把盒子当场拆开**
`auto& [key, val] = p` 的意思是：把 p 这个 pair **拆包**，第一样起名叫 key，第二样起名叫 val。之后直接用名字，不用再写 `.first` `.second`（这俩名字毫无含义，key/val 一眼看懂）：

```cpp
for (auto& [key, val] : ages)   // 每圈: 取出一个 pair, 立刻拆成 key 和 val 两个名字
    printf("%s -> %d\n", key.c_str(), val);
//                           ↑ key 是 string, val 是 int, 类型自动对号入座
```

**人话版**：map 是一抽屉"配对小盒"；range-for 每次递给你一个盒；`[key, val]` 是接过盒子的同时把盖拆了，左手拿 key 右手拿 val。

**记忆钩子**："**auto& [起的名 : 装pair的容器]**"——方括号里是给 pair 的零件**起名字**，起几个名取决于盒里有几样（pair 两样、struct 可以更多）。

⚠️ 注意 `auto&`（带引用）：遍历时改 `val` 会**真的改进 map 里**；写成 `auto [key, val]`（无&）则是拷贝，改动不影响原 map。只想读不想改时，老手写 `const auto& [key, val]`。

**自测**：`std::pair<char, double> p{'x', 3.14};` 用结构化绑定分别打印两样东西，怎么写？（`auto [c, d] = p;` 然后 printf("%c %f", c, d)——动手试，§C04.5 有完整例）

### §C04.3.2 "红黑树有序"是什么意思（map vs unordered_map）

**"有序"指遍历顺序**：不管你按什么顺序插入，**遍历 map 时 key 永远按从小到大出来**（实测：乱序插 cherry/apple/banana，遍历打出 apple banana cherry）。unordered_map 做同样的事，顺序不确定（实测同一份数据打出 banana apple cherry）。"红黑树"是 map 内部**维持这个顺序的数据结构**。

**为什么会一直有序——因为 map 内部是一棵二叉搜索树**：

```
存 cherry=3, apple=1, banana=2 后, map 内部长这样(每个节点是一个 pair):

              banana=2            ← 根(第一个插入的经过调整后不一定在根, 示意)
             /      \
        apple=1    cherry=3
        (更小放左)   (更大放右)
```

- **二叉搜索树的规矩**：任何节点，左子树所有 key 比它小，右子树所有 key 比它大。
- 插入新 key 时从根往下比大小找到空位；**中序遍历**（左→根→右）天然就是升序——apple → banana → cherry。map 的遍历就是中序遍历，所以永远有序。
- 查找 = 从根往下走，每层砍掉一半候选，所以是 **O(log n)**。

**那"红"和"黑"是干嘛的？——防退化**：
普通二叉搜索树有个致命伤：按 1,2,3,4,5 顺序插入，会长成一条向右倒的"链表"（每个都只有右孩子），查找退化成 O(n)。**红黑树 = 会自动保持平衡的二叉搜索树**：每个节点标红/黑色，插入删除破坏平衡时就通过**变色+旋转**（局部挪节点）把树扶正，保证最长路径不超过最短路径两倍——树高恒在 log(n) 附近，**插入/查找/删除稳定 O(log n)**。

**人话版**：红黑树就是一棵"**撑不死也压不扁**"的二叉搜索树——你随便怎么插，它自己转两下保持矮胖，永远 log(n) 步内找到。红黑规则的具体条文不用背（面试也很少问条文），记住这句+用途就够了。

**有序带来的超能力**：`m.lower_bound("b")` 一步找到**第一个 ≥ b 的键**——范围查询（"给我 b~d 之间的所有键"）只有 map 能做，unordered_map 做不了。

**选型口诀**：

| | map（红黑树） | unordered_map（哈希表） |
|---|---|---|
| 查找/插入 | O(log n) 稳定 | 平均 O(1) 更快, 最坏 O(n) |
| 遍历 | **key 有序** | 顺序不可预测 |
| 范围查询 lower_bound | ✓ | ✗ |
| 什么时候用 | 要有序遍历/范围查 | 只做点查处查找（绝大多数场景） |

**记忆钩子**："map 树上有序，unordered 哈希乱序；要顺序找树，要点查找哈希。"

**自测**：把 §C04.3.1 的 ages 换成 `std::map` 再遍历，输出和 unordered_map 版有什么不同？（姓名按字典序打印；lab 里有现成对照实验）

### §C04.3.3 std::hash 是什么（unordered_map 背后的"分桶器"）

**【头文件】`<functional>`**（不在 `<thread>` 里！C09 打印线程编号那行用它时容易误会）。

**作用**：把任意数据**压缩成一个 size_t 数字**——数据的"指纹"。三条性质（实测）：

```
hash("apple") = 13776597747624572848
hash("apple") = 13776597747624572848   ← 同输入必同输出(指纹稳定)
hash("banana") = 4209850087293805843   ← 不同输入→(几乎总)不同指纹
hash(42) = 42                           ← int 有专属版本
```

**它存在的意义：就是给 unordered_map 分桶用的**。你说"unordered_map 是哈希表"——
哈希表怎么知道 "apple" 该进哪号桶？`hash("apple") % 桶数`。手动模拟一遍（实测）：

```cpp
size_t bucket = std::hash<std::string>{}("apple") % 8;   // = 0 号桶
// unordered_map 内部每次 insert/find 都在干这个 ← 它 O(1) 的全部秘密
```

用法就是 C08 那个模式：`std::hash<类型>{}(值)`——临时 functor 对象当场调用。

**自创类型当 unordered_map 的 key（面试真实考点，要配两样东西）**：

```cpp
struct Point { int x, y;
    bool operator==(const Point& o) const { return x==o.x && y==o.y; }  // ②
};
template <> struct std::hash<Point> {                                   // ①
    size_t operator()(const Point& p) const {
        return std::hash<int>{}(p.x) ^ (std::hash<int>{}(p.y) << 1);    // 两个数揉一个指纹
    }
};
std::unordered_map<Point, const char*> where;
where[{3, 4}] = "仓库A";    // ✓
```

为什么缺一不可（都实测过报错原文）：
- 缺 ① hash 特化：`error: use of deleted function ...std::hash<Point>`——标准库故意把
  通用版**删掉**，逼你为自己的类型交代"指纹怎么算"（C08.4"开小灶"的真实场景）；
- 缺 ② operator==：`error: no match for 'operator=='`——不同 key 可能**撞进同一个桶**
  （哈希碰撞），桶里排队时靠 == 分辨谁才是真 key。

**人话版**：hash 是"指纹机"——它不加密、不存数据，只负责把东西变成一个数当指纹；
unordered_map 靠指纹分桶（快），撞桶了靠 == 验明正身（准）。

**记忆钩子**："hash 算指纹，% 挑桶，撞桶 == 验身；自定义 key，两样都得交。"

## §C04.5 pair 与结构化绑定

```cpp
#include <utility>
std::pair<std::string, int> p = {"gpu", 8};   // 两样东西打包
printf("%s %d\n", p.first.c_str(), p.second);
auto [name, count] = p;                       // C++17 结构化绑定: 一次拆开
```

### §C04.5.1 pair vs map：一个盒子 vs 一柜子盒子（新手常见混淆）

看着像（都是"一对一对的"），其实是**零件和容器**的关系：

| | pair | map |
|---|---|---|
| 是什么 | **一个盒子**，固定两格 | **一柜子盒子**，想装几对装几对 |
| 能装几对 | 只有 1 对 | N 对 |
| 按 key 查找 | ✗（没有查找这回事，就它自己） | ✓ `m.count("cpu")` / `m["cpu"]` |
| 内部结构 | 两个成员排排坐 | 红黑树（§C04.3.2） |
| 典型用途 | **函数一次返回两个值**、临时打包传参 | 存一堆键值对、按 key 存取 |

```cpp
std::pair<std::string, int> one = {"gpu", 8};   // 一个盒子: 就这一对, 塞不进第二对
std::map<std::string, int> many;                 // 一柜子:
many["gpu"] = 8; many["cpu"] = 16; many["npu"] = 4;
many.count("cpu");                               // 还能按 key 查(盒子里那对可没这待遇)

// 两者的关系一句话: map 里装的每个元素, 就是一个 pair ——
for (auto& p : many)          // p 的类型是 pair<const string, int>, 老熟人!
    printf("%s -> %d\n", p.first.c_str(), p.second);
```

**人话版**：pair 是**一张名片**（一张卡两栏：名字+电话）；map 是**名片盒**（一堆名片，还能按名字翻找）。名片盒里放的就是名片——map 里放的就是 pair。

**什么时候用 pair**：函数想一次带回两个结果（`std::minmax` 就返回 pair；`map::insert` 返回 `pair<iterator, bool>`——插入位置+成没成功）。**什么时候用 map**：键值对不止一对、且要按 key 管理。

**记忆钩子**："pair 一对，map 一柜；pair 是零件，map 是抽屉。"

**自测**：① 写一个函数 `first_last`，一次返回 vector 的首元素和尾元素（返回类型怎么写？）。② 超过两样想打包怎么办？（`std::tuple` 三件套，`std::get<0>(t)` 取第 i 样——用得少，知道存在即可）

## §C04.6 常用算法（`<algorithm>` / `<numeric>`）

**作用**：排序、查找、统计这些轮子别自己造。

```cpp
#include <algorithm>
#include <numeric>
std::vector<int> v = {5, 3, 8, 1};
std::sort(v.begin(), v.end());                        // 排序(默认升序)
std::sort(v.begin(), v.end(), std::greater<int>{});   // 降序
auto it = std::find(v.begin(), v.end(), 3);           // 查找, 找不到=end
int sum = std::accumulate(v.begin(), v.end(), 0);     // 求和(初始值 0), <numeric>
auto mx = *std::max_element(v.begin(), v.end());      // 最大元素
int cnt = (int)std::count_if(v.begin(), v.end(),
                             [](int x){ return x > 3; });  // 满足条件的个数 + lambda(前置:C02 §7)
std::transform(v.begin(), v.end(), v.begin(),              // 原地变换(类似 CUDA 的 elementwise kernel)
               [](int x){ return x * 2; });
std::reverse(v.begin(), v.end());                     // 反转
```

### §C04.6.1 std::transform 拆开看（它到底在干嘛）

**人话版**：transform = "**对一段范围的每个元素算一个新值，把结果写到另一个地方**"。就是 CPU 版的 elementwise kernel。

**四个参数逐个看**（这是看不懂的根源——四个参数一行放仨）：

```cpp
std::transform(v.begin(), v.end(), v.begin(), [](int x){ return x * 2; });
//              ↑1          ↑2        ↑3                  ↑4
//  1. 从哪开始读(v 的开头)
//  2. 读到哪为止(v 的结尾)      —— 1和2圈出"输入范围": [5,3,8,1]
//  3. 结果从哪开始写(v 的开头)   —— 写回 v 自己 = 原地翻倍!
//  4. 每个元素套用的函数         —— f(x) = x*2
```

**它等价于这个循环**（把这段和上面那行对看，就全懂了）：

```cpp
for (size_t i = 0; i < v.size(); ++i)
    v[i] = v[i] * 2;        // transform 干的事和这四行完全一样
```

**为什么第 3 个参数敢写回自己（原地）？** 因为 transform 是**逐个元素、从前往后**处理的：读 v[0] 算完写回 v[0]，再处理 v[1]……读写同一个位置不冲突。若第 3 参写**别的容器**（如 `w.begin()`），就是把结果存到 w，v 原样不动——那是"输出到别处"模式。

**CUDA 对照**（你的主场）：

| transform | CUDA elementwise |
|---|---|
| 输入范围 [begin, end) | kernel 读的输入指针 + N |
| 第 3 参数（写到哪） | 输出指针（in-place 时 out==in） |
| `[](int x){ return x*2; }` | kernel body 里的 `out[i] = in[i]*2` |
| 逐个从前往后 | 事实上多线程并行（这就是区别：CPU 版串行） |

**记忆钩子**：transform 三问——"**读哪段（1-2）？写哪去（3）？怎么变（4）？**"

【坑】输出位置空间不够 = 越界写（UB）。写到别的容器时，那个容器必须已经装得下（如已 resize），transform **不会**帮你扩容。

**自测**：① 把 `v * 2` 改成"负数变 0 其他不变"的 lambda 怎么写？② 想把结果写到新 vector `w`（v 不动），第 3 个参数填什么、w 要提前做什么？（答案：① `[](int x){ return x < 0 ? 0 : x; }` ② 填 `w.begin()` 且先 `w.resize(v.size())`——lab 里有现成可跑版本）

【心智模型】`std::transform` 就是 CPU 版的 elementwise kernel；`std::accumulate` 就是 reduction——
你以后在 CUDA 里写的东西，标准库早有 CPU 版对照（X03 会把两边接起来）。

## §C04.7 auto 与迭代器

**作用**：迭代器是"泛化的指针"，auto 帮你少写一长串类型。

```cpp
std::vector<int> v = {1, 2, 3};
for (auto it = v.begin(); it != v.end(); ++it) printf("%d ", *it);   // 迭代器像指针
auto x = v.begin();        // auto 推导出 std::vector<int>::iterator —— 手写太长
```

【坑】不要在遍历中 push_back/erase（可能触发扩容/失效，前置：T1-11）。
