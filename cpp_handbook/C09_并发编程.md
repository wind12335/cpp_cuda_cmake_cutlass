# C09 并发编程 【核心，CUDA host 必备】

> 多线程 = 让 CPU 同时干多件事。写 CUDA host 端（异步预热、流水线预取、监控线程）离不开。

## §C09.1 创建线程 std::thread

**作用**：启动一个并行执行流。

```cpp
#include <thread>
void work(int id) { /* ... */ }
std::thread t1(work, 1);        // 启动线程执行 work(1)
std::thread t2([]{ /* lambda 也行 */ });
t1.join();                      // 等线程结束(必须 join 或 detach, 否则程序终止报错)
t2.join();
```

【坑】线程函数抛异常没接住 → std::terminate；线程对象析构前必须 join() 或 detach()。

## §C09.2 数据竞争与 std::mutex

**作用**：两个线程同时写一个变量 = 未定义行为。mutex 保护"同一时刻只有一个线程进临界区"。

```cpp
#include <mutex>
std::mutex m;
long counter = 0;

void worker() {
    for (int i = 0; i < 100000; ++i) {
        m.lock();               // 上锁: 别人调 lock 会等
        ++counter;              // 临界区
        m.unlock();             // 解锁
    }
}
```

【前置：C06 RAII】手写 lock/unlock 在异常路径会漏 unlock——用 `std::lock_guard<std::mutex> lk(m);`
（构造加锁、析构解锁，第 16 题的经典应用）。

## §C09.3 std::atomic：无锁的原子变量

**作用**：单个变量的加减/读写不需要锁——更轻。

```cpp
#include <atomic>
std::atomic<long> count{0};
count.fetch_add(1);             // 原子自增(多线程同时调也不丢)
long v = count.load();          // 原子读
count++;                        // 运算符也支持
```

**选择标准**：保护单个变量 → atomic；保护"一段逻辑/多个变量" → mutex。
（前置：T2-22 有丢更新实测、T2-23 内存序。）

## §C09.4 条件变量：线程间的"叫醒服务"

**作用**：让线程"没活就睡，有活被叫醒"——生产者消费者模型的核心。

```cpp
#include <condition_variable>
std::mutex m;
std::condition_variable cv;
bool ready = false;

// 等待方
std::unique_lock<std::mutex> lk(m);
cv.wait(lk, []{ return ready; });   // 谓词不满足就睡(自动放锁), 被叫醒且条件成立才继续
// 通知方
{ std::lock_guard<std::mutex> lk(m); ready = true; }
cv.notify_one();                     // 叫醒一个 (notify_all 叫醒全部)
```

## §C09.5 future/async：拿"将来才有"的结果

**作用**：把一个任务丢到别的线程，主线程稍后取结果。

```cpp
#include <future>
auto fut = std::async(std::launch::async, []{ return 6 * 7; });   // 异步启动
// ... 干别的 ...
int answer = fut.get();      // 阻塞直到结果就绪 → 42
```

## §C09.6 与 CUDA 的结合【CUDA 相关】

- 每个 host 线程可以有自己的 **CUDA stream**（G06），实现"线程 A 预取数据、线程 B 监控进度"；
- CUDA context 与线程的关系：多线程共用一个 context 时要注意同步（X04 手把手）；
- `std::thread` 里调 `cudaMemcpy` 完全合法——CUDA runtime 是线程安全的（同一 context 内串行化）。
