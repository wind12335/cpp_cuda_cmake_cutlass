# C01 变量、类型与运算符 【基础】

## §C01.1 基本类型

**作用**：C++ 是静态类型语言——每个变量出生时必须声明"我是什么类型"，编译器据此分配内存、检查操作合法性。

| 类型 | 大小(x64) | 范围/用途 | CUDA 里常见吗 |
|------|-----------|----------|--------------|
| `int` | 4B | 整数（约 ±21 亿） | 索引、计数 |
| `unsigned int` / `uint32_t` | 4B | **非负**整数（0 ~ 42.9 亿） | **CUDA 索引/位运算主力** |
| `long long` / `int64_t` | 8B | 大整数（±9.2×10¹⁸） | 大小计算 |
| `unsigned long long` / `uint64_t` | 8B | 非负大整数 | 显存字节数、位掩码 |
| `float` | 4B | 单精度浮点（~7 位有效数字） | **fp32 数据，GPU 主力** |
| `double` | 8B | 双精度（~15 位） | CPU 侧累加 |
| `char` | 1B | 字符/小整数 | 字节缓冲 |
| `bool` | 1B | true/false | 条件 |
| `size_t` | 8B | **无符号**大小/长度（= unsigned 64 位） | **malloc/vector 大小必用** |
| `half`/`__nv_bfloat16` | 2B | 半精度 | **fp16/bf16 数据**（CUDA 头文件提供） |

**定宽类型（`<cstdint>`）**：`int8_t/int16_t/int32_t/int64_t` 与 `uint8_t/.../uint64_t`——
位数写死不随平台变，**CUDA/系统代码首选**（`uint32_t` 比 `unsigned int` 更常见，两者大小相同）。

### size_t vs uint64_t 辨析（长得一样，为什么要分两个名字？）

在 x64 Linux 上实测（`std::is_same`）：`size_t` 的真身是 `unsigned long`，且和 `uint64_t`
宽度相同、可互换——**值域上确实没区别**。区别在语义和平台：

- **`size_t`** = "和内存地址一样宽"的大小/数量类型：`sizeof`、`vector::size()`、`malloc` 都返回它。
  大小**跟平台走**（64 位机 8B，32 位机 4B）。写它 = 声明"这是一个大小"。
- **`uint64_t`** = "精确 64 位，任何平台不变"：位掩码、哈希值、二进制格式用。写它 = 声明
  "我需要精确位宽"。
- **`unsigned long long`**：语言关键字形式（≥64 位）。`size_t` 在 Linux x64 的真身是
  `unsigned long`，在 **Windows x64 的真身是 unsigned long long**——同物不同名，
  所以代码永远写语义别名，不写底层名字。

【实测代码】见 `labs/C01_basics.cpp` 末尾（`std::is_same` 类型对照）。

### ⚠️ 无符号数的经典陷阱（必看）

无符号数**没有负数**，"减出界"会绕回最大值（回绕）：

```cpp
unsigned u = 0;
u - 1;                  // = 4294967295 (!!), 不是 -1 —— 从 0 "下溢"绕到最大值

// 最常见事故: 和有符号数比较
int x = -1;
unsigned v = 2;
if (x < v)              // ✗ 编译器把 x 转成 unsigned → -1 变成 4294967295 → 条件为假!
    printf("永远走不到这里\n");
```

【坑】`size_t` 是无符号数：`for (size_t i = 0; i < v.size()-1; ++i)` 当 `v` 为空时
`size()-1` 下溢成巨大正数，循环体执行一次——空容器判断要先行。
【原则】**计数/索引可能出现负数时用 int；纯大小/长度/位掩码用 unsigned**；
两者不要出现在同一个表达式里（编译器 `-Wsign-compare` 会警告，开 `-Wall` 就能看到）。

## §C01.2 变量初始化（三种写法）

**作用**：给变量出生时的第一个值。不初始化的局部变量值是**随机的**（读它=未定义行为）。

### ⚠️ 先讲命名规则（新手第一坑集中地）

起名字（变量/函数/枚举成员）只有两条硬限制：
1. **C++ 关键字不能用**：`int、short、long、char、float、double、bool、void、if、else、for、
   while、class、struct、enum、return、const……`（约 95 个保留字）——`short = 4` 直接编译报错
   `expected identifier`；
2. **双下划线开头的名字别写**（`__uint8_t` 这类）：保留给编译器/标准库内部使用。
   要用无符号 1 字节类型，正确写法是 `#include <cstdint>` + `uint8_t`。
另有约定俗成：**类型名大写开头**（`Human`、`DeviceBuffer`），变量/函数小写开头——不是语法，
是全行业的可读性共识。

```cpp
int a = 42;        // 拷贝初始化（最常见）
int b(42);         // 直接初始化
int c{42};         // 列表初始化（C++11 起，推荐）：禁止窄化转换，编译器帮你抓错
// int d{3.14};    // ← 编译报错！double→int 会丢精度，列表初始化直接拦下
int e = 3.14;      // ← 合法但静默丢成 3，这种 bug 最难查
auto f = 42;       // auto: 让编译器从右边的类型推导（类型很长时救命，见 §C04.6）
```

## §C01.3 const 与 constexpr

**作用**：`const` = 只读（运行期不可改）；`constexpr` = 编译期就是常数（能当数组长度、模板参数）。

```cpp
const int n = 10;          // 运行期只读
constexpr int m = 10;      // 编译期常数
int arr[m];                // ✓ constexpr 可做数组长度; 用 const 的 n 在新编译器也可以
const double PI = 3.14159;
```

【前置：C05 §3】const 还能修饰成员函数，到类那一章展开。

## §C01.4 类型转换：static_cast

**作用**：显式地把一个类型转成另一个。C++ 要求转换必须写出来（不用 C 的 `(int)x`），让"这里有风险转换"在代码里可见。

```cpp
double d = 3.7;
int i = static_cast<int>(d);        // 3（截断小数）
size_t total = static_cast<size_t>(i) * 1024;  // 混用有无符号前先统一
float* fp = static_cast<float*>(malloc(100));  // void* → 具体指针
```

【前置：T2-29 四种 cast】面试版的四种 cast 区别在 `cpp_interview_notes/T2_14题/29`。

## §C01.5 运算符重点：位运算（CUDA 高频）

**作用**：直接操作二进制位。GPU 代码里索引计算、掩码、对齐全靠它们。

### 数字字面量的进制前缀（先搞清这个，位运算才不懵）

| 写法 | 进制 | 例子 | 值 |
|------|------|------|----|
| `11` | 十进制（无前缀） | `11` | 11 |
| `0b1011` | **二进制**（0b 前缀，C++14） | `0b1011` = 8+2+1 | 11 |
| `0xFF` | **十六进制**（0x 前缀） | `0xFF` = 15×16+15 | 255 |
| `010` | ⚠️ **八进制**（开头一个 0！） | `010` = 1×8+0 | **8**，不是 10! |

【坑】**开头的 0 表示八进制**：`010` 是 8 不是 10——手写对齐时最容易被坑，写二进制永远用 `0b` 前缀。
【便利】C++14 允许单引号分隔：`0b1011'1010`（按 4 位分组可读性极强）。
【CUDA 相关】掩码常用 `0xFF`（低 8 位）、`0xFFFFFFFF`（32 位全 1）；hex 的好处是 2 的幂一眼可辨
（`0x1000` = 4096）。

```cpp
int x = 0b1011;         // 0b 前缀写二进制 = 11 (8 + 2 + 1)
int bit3 = (x >> 2) & 1;       // 取第 2 位: 右移 2 位再 &1 → 0
int y = x << 1;                // 左移 1 位 = 乘 2 (22)
int z = x & 0xFF;              // & 0xFF = 只保留低 8 位（CUDA 里 i&1、i&0xFF 常见）
bool odd = x & 1;              // 最低位是 1 → 奇数
int aligned = (sz + 255) & ~255;  // 向上对齐到 256 的倍数（内存对齐常用套路）
```

| 运算 | 含义 | 例子 |
|------|------|------|
| `a << k` / `a >> k` | 左移/右移 | `1<<10` = 1024（CUDA 里 `1<<20`=1M 个线程） |
| `a & b` | 按位与：两边都 1 才是 1（筛子/取交集） | 掩码、取低位 |
| `a \| b` | 按位或：有 1 就是 1（拼装/置位） | 拼标志位 |
| `a ^ b` | 异或：不同才是 1（找差异） | swizzle 重排（CUDA 第 17 题） |
| `~a` | 按位取反 | `& ~255` = 清低 8 位 |

**逐位验证例题**（自己先算一遍再看答案）：

```
0b1011 & 0b1100 = 0b1000   (8)    1&1=1, 其余三位至少一边是 0 → 0
0b1011 | 0b1100 = 0b1111   (15)   每一位至少一边是 1 → 全 1
0b1011 ^ 0b1100 = 0b0111   (7)    最低三位不同→1, 最高位相同→0
```

真值表（背这三行就够）：`AND: 1&1=1 其余 0`；`OR: 0|0=0 其余 1`；`XOR: 相同得 0 不同得 1`。

## §C01.6 枚举 enum class

**作用**：**发明一个新类型 + 规定它只允许的取值清单**。一句话纠正常见误解：
`enum class Mode { Train, Infer };` **没有创建任何对象/变量**——它做两件事：
①定义新类型 `Mode`；②给它配一份"合法取值菜单"（`Mode::Train` 和 `Mode::Infer` 是菜单上的
**常量**，默认 Train=0、Infer=1，不是变量！）。真正的变量在使用时才创建：

```cpp
Mode m = Mode::Train;     // ← 这里才创建了 1 个变量 m, 取值为菜单项 Train
m = Mode::Infer;          // 换成菜单上另一项
// m = 5;                 // ✗ 编译错! 5 不在菜单上 —— 取值被类型系统锁死
// m = 0;                 // ✗ 连"看着像的整数"也不收(enum class 的强类型)

// 为什么需要它? 对比"老写法":
const int MODE_TRAIN = 0, MODE_INFER = 1;
int old = MODE_TRAIN;
old = 999;                      // ✗ 编译通过! 非法值悄悄埋下 bug —— 这就是 enum 要解决的
void save(int mode);            // save(3.7) 都能过

void save(Mode mode);           // enum 版: 只能传 Mode, 非法值编译期拦截
switch (mode) {
    case Mode::Train:  /* ... */ break;
    case Mode::Infer:  /* ... */ break;
}
```

【三个收益】①取值锁死在菜单内；②强类型（不与 int 互转）；③带作用域（必须写 `Mode::Train`，
不会与外界同名变量冲突——旧式 enum 的著名缺点）。
【自定义底层值】`enum class Precision : uint8_t { FP32, FP16 = 10, BF16 };`（默认从 0 递增，
也可手动指定）。

### ⚠️ 三个高频误解（实测澄清，本机运行验证）

1. **`enum class P : uint8_t` 里的 `: uint8_t` 不是继承**（虽然长得像 `class Dog : Animal`）——
   它指定的是**底层存储类型**："这个枚举的值用 1 字节无符号数存放"。enum 也不能继承类。
   意义 = 控制内存：默认底层 int 占 4 字节，指定 uint8_t 只占 1 字节
   （`sizeof` 实测分别为 4 和 1）——显存里存百万个标记时差 4 倍。
2. **没写值的项 = 前一项 +1**：`{ FP32 = 0, FP16 = 10, BF16 }` → FP32=0, FP16=10,
   **BF16=11**（不是别的数；常量名里的"16"只是标签，与值无关）。
3. **枚举定义时不创建任何对象**——它只发明"类型 + 取值菜单"；变量是你用时才建的，
   每个变量占 1 字节（底层类型多大就占多大）。
【CUDA 相关】精度模式（FP32/FP16/BF16/INT8）、kernel 状态机、运行阶段（Forward/Backward）
都适合用 enum class 表达——PyTorch 里 `torch::kFloat`/`torch::kHalf` 就是这类东西。

### 📝 自测例题（先自己算，再看答案）

```cpp
enum class Level { LOW = 5, MID, HIGH = 20, TOP };
// LOW=?  MID=?  HIGH=?  TOP=?
```

**答案**：LOW=**5**（手动指定）→ MID=**6**（没写 = 前一项 5 + 1）→ HIGH=**20**（手动指定，
计数"跳轨"重新开始）→ TOP=**21**（没写 = 前一项 20 + 1）。

核心规则一句话：**没写值的项 = 前一项的值 + 1**（跟着前面那个数走，与"它是第几个"无关；
一旦某项手动指定了值，后面的计数就从新值继续）。

## §C01.7 运算符速览

```cpp
int a = 7, b = 2;
a / b;        // 3   ← 整数除法截断！想得 3.5 写 static_cast<double>(a)/b
a % b;        // 1   取余
++a; a++;     // 前置(先加后用) / 后置(先用后加)
a += b;       // 等价 a = a + b（-= *= /= 同理）
a == b; a != b; a && b; a || b; !a;   // 比较/逻辑（&&和||有短路：左边确定就不算右边）
```

【坑】`a / b` 当 b 是 0 → 崩溃；整数和浮点混合运算时，先算的那对决定规则（`1/2*4.0`=0，`1.0/2*4`=2）。
