# C02 控制流与函数 【基础】

## §C02.1 分支：if / else / switch

**作用**：让程序按条件走不同路径。

```cpp
int x = 42;
if (x > 100) {
    printf("big\n");
} else if (x > 10) {
    printf("medium\n");
} else {
    printf("small\n");
}

// C++17 带初始化的 if：把"临时变量"限制在 if 作用域里，防止泄漏到外面
if (auto n = x * 2; n > 50) {
    // n 只在这里可用
}
```

### §C02.1.1 带初始化的 if 与 auto（新手详解）

`if (auto n = x * 2; n > 50)` 看着像 for 不是错觉——它和 for 是**同一个语法家族**：
`for (初始化; 条件; 步进)`，`if (初始化; 条件)`。初始化部分先执行一次，然后判断条件。

**auto 是什么**：一个关键词，意思是"**编译器，从右边的值自己推断类型**"——
它不是动态类型，类型在编译期就定死：

```cpp
auto i = 42;      // 42 是 int → i 是 int
auto d = 3.14;    // 3.14 是 double → d 是 double
auto n = x * 2;   // x 是 int → n 是 int
```

**为什么要带初始化**（对比旧写法）：

```cpp
// 旧写法: n 声明在外面, 出了 if/else 还活着, 可能被误用
int n = x * 2;
if (n > 50) { /* ... */ }
printf("%d", n);        // n 还在, 万一被人用了"过期的 n"呢?

// 新写法: n 被锁死在 if/else 作用域内, 外面用 n 直接编译报错
if (auto n = x * 2; n > 50) { /* ... */ }
```

三个好处：①不污染外层作用域；②一眼看出"这个变量仅为这次判断服务"；③杜绝误用过期值。
**原则：变量作用域越窄越好**（和 range-for 里 `for (auto& e : v)` 同一思想）。
【前置：C01 §C01.2 auto 的基本用法】

### §C02.1.2 switch：一个变量的多值分发（基础版）

```cpp
switch (x % 3) {
    case 0: printf("余0\n"); break;   // 忘写 break 会"贯穿"到下一个 case —— 经典 bug
    case 1: printf("余1\n"); break;
    default: printf("其他\n"); break;
}
```

### §C02.1.3 switch 的 default 不是必须的

```cpp
switch (x % 3) {
    case 0: printf("余0\n"); break;
    case 1: printf("余1\n"); break;
    // 不写 default: 完全合法。当 x%3==2 时 → 整个 switch 被跳过, 一行不执行, 也不报错
}
```

有时"不匹配就什么都不做"正是想要的。但工程建议：**对枚举的 switch 几乎总要写 default**
（哪怕只打印"未知值"）——将来枚举加了新值，它就是防漏处理的安全网。
另外 default 写在哪都可以（不必须在最后），习惯放最后。

## §C02.2 循环：for / while / range-for

**作用**：重复执行。

```cpp
// 经典计数循环
for (int i = 0; i < 10; ++i) { /* ... */ }

// range-for（C++11 起）：遍历"一切有 begin/end 的东西"，最常用
std::vector<int> v = {1, 2, 3};
for (int e : v) printf("%d ", e);         // 只读
for (int& e : v) e *= 2;                  // 要修改元素就用引用 int&（前置：C03 §3 引用）

// while: 事先不知道次数
int n = 100;
while (n > 1) n /= 2;

// break 立即跳出整个循环; continue 跳过本轮进入下一轮
```

【坑】range-for 里 `for (auto e : v)` 是**复制**每个元素（大对象性能差），只读时写 `for (const auto& e : v)`。

### §C02.2.1 三种 range-for 写法对照（新手详解）

**`for (int e : v)`**：每轮把元素**复制一份**装进 e——e 是副本，改它不影响 v。
**`for (int& e : v)`**：e 是元素本尊的**别名**（不是"取地址"——引用=另一个名字），
改 e 就是改 v 里的元素。**`for (const int& e : v)`**：只读别名——不复制也不许改。

眼见为实（打印地址：别名版的 &e 就是 &v[i]，副本版的 &e 是另一块栈内存）：

```cpp
std::vector<int> v = {10, 20};
for (int& e : v) printf("别名版 &e=%p\n", (void*)&e);     // 和 &v[0]、&v[1] 相同!
for (int e : v)  printf("副本版 &e=%p\n", (void*)&e);     // 每轮一个新地址(栈上的副本)
```

| 写法 | e 是什么 | 改 e 影响 v？ | 什么时候用 |
|------|---------|--------------|-----------|
| `for (T e : v)` | 副本 | ❌ | 小对象只读（int/float） |
| `for (T& e : v)` | 元素本尊 | ✅ | **要修改**元素 |
| `for (const T& e : v)` | 只读别名 | ❌ | **大对象只读**（string/vector，避免每轮复制） |

## §C02.3 函数定义、声明与头文件

**作用**：把一段逻辑封装成可复用的单元。

```cpp
// 定义（有函数体）
int add(int a, int b) { return a + b; }

// 声明（只有签名，告诉编译器"它存在，定义在别处"）—— 通常写在头文件 .h 里
int add(int a, int b);

// 函数必须先声明后使用：main 里调 add 之前，编译器要见过上面两行之一
```

**主流程**：`.h` 头文件放声明，`.cpp` 源文件放定义，谁用谁 `#include "xxx.h"`。

## §C02.4 参数传递：值 / 引用 / 指针 【核心】

**作用**：决定"函数拿到的是副本还是原件"——性能和正确性都取决于此。

```cpp
void byValue(int x)  { x = 100; }     // 拿到副本，改它不影响外面
void byRef(int& x)   { x = 100; }     // 引用 = 原件的别名，改它=改外面（前置：C03 §3）
void byPtr(int* x)   { *x = 100; }    // 指针传址，调用方写 f(&a)

int main() {
    int a = 1;
    byValue(a);  // a 还是 1
    byRef(a);    // a 变成 100
}
```

**约定**：大对象只读 → `const std::string&`（不拷贝又改不了）；要修改 → `T&`；
可选参数/需要"没有"状态 → 指针。

## §C02.5 函数重载与默认参数

**作用**：同名函数按参数类型/个数区分。

```cpp
int  maxOf(int a, int b)          { return a > b ? a : b; }
double maxOf(double a, double b)  { return a > b ? a : b; }   // 重载: 参数类型不同

void launch(int blocks, int threads = 256) {   // 默认参数: 不传就用 256
    // ...
}
launch(32);        // threads 自动 = 256
launch(32, 512);   // 显式给 512
```

【前置：C05 §2】类的构造函数也有默认参数，配合 explicit 使用（面试第 27 题）。
【补充】重载**不是类的专利**——类外的自由函数（如上例）随便重载；与模板的关系：
模板 = "编译器自动生成一族重载"的机器（前置：C08.1）。

## §C02.6 static 详解 【核心，新手必读讲透版】

**一句话模型：static = "改变变量的默认命运"**。普通变量有两个默认命运，static 分别背叛它们：

| 位置 | 默认命运 | static 改成了 |
|------|---------|--------------|
| 函数内局部变量 | 活在栈上，**函数一退出就死**，每次进来重新出生 | 第一次执行到才出生，**程序结束才死**（有记忆！）|
| 全局变量/函数 | 程序启动就存在，**整个工程都能看见** | 只有**本 .cpp 文件**能看见（文件私有）|
| 类的成员 | 每个对象各一份 | **全类共享一份** |

### 场景 1：函数内 static —— "给函数加记忆"（最常用）

```cpp
int callCount() {
    static int count = 0;    // 只在【第一次调用】时初始化; 之后跳过这行, 沿用上次的值
    return ++count;
}
callCount();  // 1
callCount();  // 2   ← 普通局部变量每次都是 1
```

三大实战场景：①调用计数/限流；②**单例**（全局唯一配置：`static Config inst; return inst;`）；
③昂贵的查找表只建一次（第一次算好，之后直接查）。
【坑】局部 static 的"初始化只一次"在 C++11 起是线程安全的（多线程同时首次调用也只构造一次）——
但初始化**之后**的多线程读写仍要自己加锁（前置：C09）。

### 场景 2/3：类的 static 成员变量 / 成员函数

```cpp
class Kernel {
public:
    static inline int alive = 0;        // 全类共享一份(不属于任何单个对象)
    static int reportAlive() {          // 静态成员函数: 没有 this,
        return alive;                    //   只能碰静态成员; 不需要对象就能调用
    }
    Kernel() { ++alive; }
    ~Kernel() { --alive; }
};
Kernel::reportAlive();   // 不创建对象直接调
```

用途：对象存活计数（资源池统计）、全局配置、工厂函数。普通成员 `local` 每对象各一份；
静态成员全体共享——它没有 this，所以碰不了普通成员（前置：T3-33）。

### 场景 4：全局 static —— "本文件的私有工具"

```cpp
static int helper(int x) { ... }   // 只在本 .cpp 可见; 别的文件写同名函数也不冲突
```

多人协作防命名冲突（现代等价写法：匿名命名空间 `namespace { ... }`）。

### 什么时候【不】用 static

①多线程同时读写同一个 static 变量要加锁（前置：C09）；②别把 static 当"全局变量筐"乱塞
状态——全局可变状态越多，bug 越难排查。

## §C02.7 lambda 表达式（C++11）【核心】

**作用**：就地定义一个匿名函数，常用于"一次性逻辑"（排序规则、回调、线程任务）。

```cpp
// 基本形态: [捕获列表](参数) -> 返回类型 { 函数体 }
auto square = [](int x) { return x * x; };
printf("%d\n", square(5));    // 25
```

### §C02.7.1 捕获列表完整速查（新手最常混乱的地方）

**先立规矩：捕获列表 `[]` 里只能写"变量名"，永远不能写类型**——类型写在后面的
`(参数列表)` 里。`[int x]` 是语法错误；捕获列表回答的问题是
"除了参数，还要从外界带哪些东西进来"。

| 写法 | 含义 |
|------|------|
| `[]` | 什么都不捕获（不需要外界任何变量） |
| `[x]` | 按值捕获 x（复制一份快照，改它不影响原件） |
| `[&x]` | 按引用捕获 x（就是原件，改它=改原件） |
| `[=]` | 用到的外部变量**全部按值**（快照） |
| `[&]` | 用到的外部变量**全部按引用** |
| `[x, &y]` | 混合：x 按值，y 按引用 |
| `[=, &y]` | 默认按值，特例 y 按引用 |
| `[&, x]` | 默认按引用，特例 x 按值 |
| `[this]` / `[*this]` | 类内捕获对象指针 / 对象拷贝（C++17） |
| `[p = std::move(p)]` | 初始化捕获（C++14）：把移动语义带进闭包 |

【⚠ 最大坑，前置：T1-19 悬垂】`[&]` 捕获的引用在变量死后就是废纸——lambda 被存起来
异步执行时再调用 = 未定义行为。**规矩：同步立即用 → `[&]` 省事；要逃逸作用域（线程/回调）
→ 按值捕获或捕获智能指针的拷贝**。
【`[+]`？】不存在这种捕获。你可能见过 `+[](){...}`——`+` 在捕获列表**外面**，
是把无捕获 lambda 转函数指针的小技巧，极少用。

### §C02.7.2 [=] / [&] / 混合 完整演示

```cpp
int a = 1, b = 2;
auto sumAll = [=] { return a + b; };          // a、b 复制快照进来
auto sumRef = [&] { return a + b; };          // a、b 引用原件
auto mixed  = [=, &b] { b = 99; return a; };  // 默认按值, 特例 b 按引用

a = 100;
sumAll();   // 3    (快照: 1+2, 不受 a=100 影响)
sumRef();   // 102  (引用: 100+2, 看到新值)
```

【补充】按值捕获的副本默认不可修改——要改加 `mutable`：`[x]() mutable { ++x; }`。
【前置：T3-36 std::forward 完美转发——emplace_back 能就地构造的机制】

### §C02.7.3 两个最常用的实战场景

```cpp
// 场景 1: 给 sort 定排序规则 (无捕获)
std::vector<int> v = {3, 1, 2};
std::sort(v.begin(), v.end(), [](int a, int b) { return a > b; });   // 降序

// 场景 2: 捕获外界变量 (按值 vs 按引用)
int bias = 100;
auto addBias = [bias](int x) { return x + bias; };   // 值捕获: 复制了一份
auto addRef  = [&bias](int x) { bias += x; };        // 引用捕获: 改的是原件
printf("%d %d\n", addBias(5), addRef(5));            // 105 105
```

【前置：T2-19 捕获的坑】按引用捕获 + lambda 活得比变量久 = 悬垂，面试高频。

## §C02.8 递归

**作用**：函数调用自己。必须有终止条件，否则爆栈（前置：C03 §5 栈）。

```cpp
long long fact(int n) { return n <= 1 ? 1 : n * fact(n - 1); }
```

CUDA 视角：GPU 上递归要靠显存模拟调用栈，慢且危险，kernel 里几乎总是改成循环/显式栈。
