# C03 指针、引用与内存模型 【核心】

> 这是 C++ 最重要的一章。CUDA 里 `cudaMalloc` 返回的指针、kernel 参数传递、host/device 数据搬运，全建立在本章概念上。

## §C03.1 指针：存"地址"的变量

**作用**：指针的值 = 另一个变量在内存里的**门牌号**。通过指针可以间接读写那个变量。

```cpp
int a = 42;
int* p = &a;      // &a = 取 a 的地址; p 的类型 int* 表示"指向 int 的指针"
printf("%p\n", (void*)p);   // 打印地址 (%p 格式)
printf("%d\n", *p);         // *p = 解引用: 顺着地址找到 a 本身 → 42
*p = 100;                   // 通过指针修改 a → a 现在是 100
```

- `&x` 取地址；`*p` 解引用（顺藤摸瓜）。
- 【坑】**野指针**：没初始化的指针指向随机地址，解引用=崩溃。声明时先 `int* p = nullptr;`

### §C03.1.1 void 与 void*（两个"void"不是一回事）

```cpp
void f();              // ① 函数的 void = "不返回任何东西"
void* p;               // ② void* = 通用指针: 只存地址, 不知道指向的类型/大小
```

`void*` 三条规则：①任何对象指针都能**隐式转成** void*（存地址不需要知道类型）；
②**解引用前必须转回**具体类型（`static_cast<int*>`，否则编译器不知道读写几字节）；
③**不能做算术运算**（不知道步长几字节）。

```cpp
void* vp = &a;                          // ✓ 任意指针 → void*
int* back = static_cast<int*>(vp);      // 转回具体类型才能解引用 (前置：T2-29)
*back = 5;
printf("地址 = %p\n", (void*)p);        // %p 的约定是打印 void* —— 显式转换表意图+消警告
```

**为什么 printf 地址要写 `(void*)p`**：`%p` 的约定就是"打印 void*"，显式转换 = 表达意图 +
消除 -Wall 警告（任意指针→void* 无损安全，和 T2-29 里危险的 reinterpret 场景不是一回事）。

**【CUDA 连接】`cudaMalloc` 的签名是 `cudaMalloc(void** devPtr, ...)`**——第一参数就是
"通用指针的指针"，所以你的 `float* d_a` 直接传 `&d_a` 不用强转：函数只往里写一个地址，
不需要知道你是什么类型。这是 void* 在真实 GPU API 里的标准用法。

## §C03.2 nullptr：空指针

**作用**：表示"这个指针不指向任何对象"。判断指针可不可用之前，先判空。

```cpp
int* p = nullptr;
if (p != nullptr) { *p = 1; }         // 用之前判空
// C++11 后可以简写: if (p) { *p = 1; }   nullptr 在条件里就是 false
```

【前置：C11 nullptr vs NULL】NULL 是 C 时代遗留的宏（本质是 0），会引发重载歧义，C++ 一律用 nullptr。

## §C03.3 引用：变量的别名

**作用**：引用是变量的**另一个名字**，语法上像值、语义上像指针（但更安全）。

```cpp
int a = 42;
int& r = a;       // r 是 a 的别名, 出生时必须绑定, 且终生不改绑
r = 100;          // 改 r 就是改 a → a=100
printf("%d %d\n", a, r);   // 100 100
```

## §C03.4 指针 vs 引用（面试高频）

| | 指针 `int*` | 引用 `int&` |
|---|---|---|
| 可以为空 | ✅ nullptr | ❌ 必须绑定 |
| 可以改绑 | ✅ p 可指向别人 | ❌ 终生绑定一个 |
| 需要解引用 | ✅ `*p` | ❌ 直接当变量用 |
| 能做算术 | ✅ p+1 | ❌ |

**工程口径**：能用引用就用引用（安全），需要"可空/可改指/遍历内存"才用指针。

## §C03.5 栈与堆：两块内存

**作用**：变量住在两块不同的地方，规则完全不同（前置：cpp_interview_notes T1-15 有完整对比与实测）。

```cpp
void f() {
    int stack_var = 1;              // 栈: 函数进出自动管理, 快, ~8MB 上限
    int* heap_var = new int(2);     // 堆: 手动申请, 大, 但必须手动/智能指针释放
    delete heap_var;                // 忘了 delete = 内存泄漏
}
// 【坑】返回局部变量的指针/引用 → 函数返回后那块栈内存作废 → 悬垂!
int* bad() { int x = 5; return &x; }   // ✗ 绝对不要
```

【前置：C06 智能指针】现代 C++ 用 RAII/智能指针让"忘 delete"不可能发生。

## §C03.6 数组与指针退化

**作用**：数组名在传参时会"退化"成指针，丢失长度信息——所以要额外传长度。

```cpp
void printArr(int* arr, size_t n) {   // 接收方不知道 n, 必须额外传
    for (size_t i = 0; i < n; ++i) printf("%d ", arr[i]);
}
int a[5] = {1, 2, 3, 4, 5};
printArr(a, 5);       // a 在这里退化成 int*
```

【CUDA 相关】`cudaMalloc` 得到的设备指针同样只是个地址——host 代码**不能直接解引用它**，
必须用 `cudaMemcpy` 搬运或传给 kernel（X01 详解）。

## §C03.7 指针算术与多级指针

```cpp
int a[5] = {10, 20, 30, 40, 50};
int* p = a;             // 指向 a[0]
p + 1;                  // 地址 +4 字节(int 的大小)——指针算术按"元素"走
*(p + 2);               // 等价 a[2] = 30;  事实上 a[i] 的定义就是 *(a+i)
int** pp = &p;          // 二级指针: 指向"指针的指针"(CUDA host 端 cudaMalloc 参数要 &ptr 正是这理)
```

【CUDA 相关】`cudaMalloc(&d_ptr, bytes)` 的第一个参数就是"指针的指针"：函数要往**你给的位置**里
写入它分配的地址——所以传 `&d_ptr`。

## §C03.8 const 与指针的组合

```cpp
const int* p1;        // 指向常量: *p1 不可写, p1 可挪 (常用来表示"我只读")
int* const p2 = &a;   // 指针常量: p2 不可挪, *p2 可写
const int* const p3 = &a;   // 都不可
```

口诀（前置：T2-20 const 全用法）：**左定值右定针**。

## §C03.9 进程内存五区全景（+ 类成员住哪）【理解，抛砖引玉】

**作用**：把"全局变量区、代码区、常量区、堆、栈"统一成一张地图——类成员变量/函数住在哪
一次说清（地址从低到高）：

```
低地址 ┌──────────────────────────────┐
       │ 代码区 .text                 │ ← 所有函数的机器码【每个函数只有一份】
       ├──────────────────────────────┤   (成员函数也在这, 不管多少个对象)
       │ 只读区 .rodata               │ ← 字符串字面量、const 全局量、虚表(vtable)
       ├──────────────────────────────┤
       │ 全局/静态区 .data + .bss     │ ← 全局变量、static 局部变量、static 类成员
       ├──────────────────────────────┤
       │ 堆 heap                      │ ← new/malloc(向高地址生长)
       ├──────────────────────────────┤
       │ ... 空闲 / 动态库 ...        │
       ├──────────────────────────────┤
       │ 栈 stack                     │ ← 局部变量、函数帧(向低地址生长, ~8MB)
高地址 └──────────────────────────────┘
```

### 类成员住哪（最易混，一张表钉死）

| 东西 | 住哪 | 几份 |
|------|------|------|
| 非静态**成员变量** | **对象内部**（对象在栈则它在栈；对象 new 在堆则在堆）| 每对象一份 |
| **成员函数** | **代码区**（本质是普通函数 + 隐藏的 this 参数，前置 T3-33）| 全类**只有一份** |
| static 成员变量 | 全局/静态区 | 全类一份 |
| 虚表(vtable) | 只读区 | 每类一份；对象里只有 vptr 指向它（前置 T1-01）|

**结论**：`Vec3 v[1000000];` 占内存的是 300 万字节的成员变量；100 万个对象共享同一份函数
代码——"成员函数在每个对象里都有一份"是初学者最普遍的误解，函数永远在代码区，只有**数据**
跟对象走。【验证：labs/C03_pointers.cpp 的"内存五区全景"段把六类地址全部打出来排序】
