# C05 类与对象 【核心】

> 面向对象三件套：**封装**（数据+函数打包）、**继承**（复用与扩展）、**多态**（同一接口不同实现）。

## §C05.1 类的基本结构：成员、构造、析构

**作用**：把数据和操作打包成一个自定义类型。

```cpp
class Vec3 {
public:                     // public: 外部可访问
    float x = 0, y = 0, z = 0;              // 成员变量(带默认值, C++11 起)

    Vec3() = default;                        // 默认构造: 不给参数时用
    Vec3(float x_, float y_, float z_)       // 带参构造
        : x(x_), y(y_), z(z_) {}             // 初始化列表(第 20 题"产房")

    float dot(const Vec3& o) const {         // 成员函数; 末尾 const=不修改自己
        return x*o.x + y*o.y + z*o.z;
    }

private:                    // private: 外部不可访问(封装)
    int id_ = 0;
};

Vec3 a(1, 2, 3), b(4, 5, 6);
printf("%f\n", a.dot(b));    // 32
```

【前置：T2-20】const 成员函数与 mutable；【坑】`Vec3 v();` 这不是构造对象！这是"声明一个函数"，
最著名解析陷阱之一，无参构造要写 `Vec3 v;` 或 `Vec3 v{};`。

## §C05.2 构造函数家族

**作用**：控制对象"怎么出生"。

```cpp
#include <cstring>   // std::memcpy
class Buf {
public:
    Buf(size_t n) : len_(n), data_(new char[n]) {}   // 普通构造
    Buf(const Buf& o) : len_(o.len_),                // 拷贝构造: 深拷贝(前置：T1-17)
                        data_(new char[o.len_]) {    //   重新开一块, 内容抄过来
        std::memcpy(data_, o.data_, o.len_);
    }
    Buf(Buf&& o) noexcept                            // 移动构造: 偷指针(前置：C07)
        : len_(o.len_), data_(o.data_) {
        o.data_ = nullptr;                           //   源头置空, 防止两个对象都 delete 它
    }
    Buf& operator=(const Buf& o) {                   // 拷贝赋值: 五步完整版
        if (this != &o) {                            // ① 防自赋值(b = b 时啥也不干)
            char* fresh = new char[o.len_];          // ② 先开新空间(若在这里抛异常,
            std::memcpy(fresh, o.data_, o.len_);     //    旧的还没被删, 对象仍完好=异常安全)
            delete[] data_;                          // ③ 新的到手了才删旧的
            data_ = fresh;                           // ④ 接管
            len_ = o.len_;
        }
        return *this;                                // ⑤ 返回自己, 支持 a = b = c 链式
    }
    Buf& operator=(Buf&& o) noexcept {               // 移动赋值: 四步完整版
        if (this != &o) {                            // ① 防自移动(b = std::move(b) 是灾难)
            delete[] data_;                          // ② 释放自己的
            data_ = o.data_;                         // ③ 偷对方的
            len_ = o.len_;
            o.data_ = nullptr;                       // ④ 源头置空
        }
        return *this;
    }
    ~Buf() { delete[] data_; }                       // 析构
private:
    size_t len_;    // 先声明 len_(初始化列表按声明顺序执行, 保持一致防警告)
    char* data_;
};
```

> **勘误**：本例早期版本写成 `data_(new char[*o.len_])`——两处错误：当时类里根本没有
> `len_` 这个成员；而且那个 `*` 是错的（`new char[n]` 要的是**元素个数**，`o.len_` 本身
> 就是 size_t 数字，直接用。`*` 解引用**只能用于指针**，对 int/size_t 用 `*` 编译器报
> `invalid type argument of unary '*'`）。感谢读者抓 bug——**看到 `*` 先问自己：这是指针吗？**

**人话版（五个函数各管什么）**：构造=出生；拷贝构造=照着别人**重新生**一个（深拷贝）；
移动构造=把别人的**家当直接搬走**（源头置空）；拷贝赋值=把别人家的**抄进**我家（先抄到新的、再扔旧的）；
移动赋值=扔掉我的、搬进别人家当；析构=临走把家当**还掉**（delete）。

**记忆钩子**：拷贝 = "抄"，移动 = "偷"（偷完把空钱包还给对方）；两个赋值都要**防自赋值**、**返回 \*this**。

### §C05.2.1 noexcept 是什么（为什么移动函数都贴它）

**noexcept = 函数对编译器的承诺书："我不抛异常"**。写在参数列表后：

```cpp
void f() noexcept;            // 承诺不抛
void g() noexcept(true);      // 同上(true 可省)
void h() noexcept(cond);      // 按条件决定(模板里常见)
```

**违约后果**：noexcept 函数里真抛了异常 → 不是被 catch，而是直接 `std::terminate()` **当场崩程序**。所以它是个严肃承诺，不能随手贴。

**那为什么移动构造/移动赋值要贴？——为了 vector 扩容时敢用移动**：

vector 满了要扩容（搬家到更大的新家），要把旧元素搬过去。这时它面临选择：

- 用**移动**（偷指针，快）——但万一搬到一半某个移动抛异常，新家一半旧家一半，状态稀碎，vector 的"扩容要么成功要么原样"保证就破产了；
- 用**拷贝**（慢，但旧元素原样不动）——中间抛异常也只是白干，旧数据完好。

所以标准规定：**只有移动构造标了 noexcept，vector 扩容才敢用移动；没标，就默默退回拷贝**——你的"移动"根本不会在扩容时被用上，性能白丢。这是 noexcept 存在的头号理由，也是面试高频题（实测对照见 `labs/C05_classes.cpp` 末尾的实验：同样一个类，移动函数加不加 noexcept，push_back 扩容时的"拷贝数/移动数"天差地别）。

**人话版**：noexcept 就是跟搬家公司签的"**保证途中不出岔子**"合同——vector 只敢把家具（元素）交给签了合同的搬家公司（noexcept 移动）整车搬走；没签合同的公司，它宁可一件件复印一份（拷贝），慢就慢，出事能复原。

**记忆钩子**："**移动必 noexcept，否则 vector 不敢用**；承诺不抛，抛了就崩。"

【延伸，看不懂可跳】析构函数 C++11 起**隐含 noexcept**（析构抛异常没人接得住）；`noexcept(f())` 还能当编译期布尔用（配合模板 SFINAE/约束，C11 速查表里有）。

### §C05.2.2 `Vec3&&` 是什么（提前认识右值引用，详见 C07）

`&&`（两个&连写）是**右值引用**——C++11 新增的引用类型。和 `&` 对照着记：

| 写法 | 名字 | 只能绑谁 | 比喻 |
|---|---|---|---|
| `Vec3&` | 左值引用 | 有名字、还要继续用的对象 | 常住居民的通讯录 |
| `const Vec3&` | const 左值引用 | **谁都能绑**（只读，左右值通吃） | 只读阅览证 |
| `Vec3&&` | 右值引用 | **只绑临时/即将销毁的**（右值） | 临终遗嘱签名处 |

**它存在的意义：给编译器"分流"的标签**。当你同时提供两个重载：

```cpp
void who(const Vec3&);   // 拷贝版: 参数还要用, 我只能小心抄
void who(Vec3&&);        // 移动版: 参数是临时货, 我可以合法掏空它(偷指针)
```

编译器按"传进来的东西是不是快死了"自动选（实测）：

```
who(a);            → const Vec3&   // a 有名字还要用 → 拷贝版
who(Vec3{});       → Vec3&&        // 临时对象 → 移动版
who(std::move(a)); → Vec3&&        // a 被贴上"我不再用它"标签 → 移动版
```

**人话版**：`Vec3&& other` 这个参数的意思是"**我只接收马上要销毁的对象**，所以我可以放心把它掏空"。没有这个专用通道，编译器分不清"这个参数以后还用不用"，只敢走安全但慢的拷贝——`&&` 就是那个"我放弃它了"的声明通道。

**记忆钩子**："一个& 接活的，两个& 接死的；std::move 只贴'临终'标签，本身不搬东西。"

【衔接】左值/右值完整定义、std::move 的真相、移动后源对象状态 → C07 移动语义篇讲透。你 main 里 `Vec3 v3 = v1 + v2;` 走拷贝构造（而非移动），正是因为类里还没有 `Vec3&&` 版的构造——补上移动构造后自动分流。

### §C05.2.3 explicit：禁止构造函数被偷偷用于隐式转换

**explicit 修饰单参数构造函数 = 告诉编译器"想变成我这个类，必须明写，不许悄悄转"**。

没有 explicit 会发生什么（危险之处）——单参数构造函数天生是一条"隐式转换规则"：

```cpp
struct Seconds { double v; Seconds(double s) : v(s) {} };        // 无 explicit
void wait(Seconds s);
wait(3.0);          // ✓ 编译过! 3.0 被悄悄转成 Seconds(3.0) —— 你根本没写这个转换
Seconds s = 5.0;    // ✓ 同样悄悄转(拷贝初始化也走这条路)

struct Meters { double v; explicit Meters(double m) : v(m) {} }; // 有 explicit
void climb(Meters m);
climb(Meters(100.0));  // ✓ 转换显式可见
Meters m(200.0);       // ✓ 直接初始化永远合法
climb(100.0);          // ✗ 编译错: conversion from 'double' to non-scalar type 'Meters' requested
Meters m2 = 5.0;       // ✗ 编译错(同上)
```

**危险在哪**：`wait(3.0)` 里那个转换**不是你写的、也不显眼**——参数类型差着辈分却默默编译通过，单位/语义错误全被吞掉（3.0 秒 vs 3.0 米）。隐式转换链一长，事故排查极其痛苦。

**智能指针的裸指针构造必须 explicit（你手搓 SharedPtr 骨架里那行的意义）**：

```cpp
std::unique_ptr<int> p(new int(5));   // ✓
std::unique_ptr<int> q = new int(6);  // ✗ error: conversion from 'int*' to
                                      //   'std::unique_ptr<int>' requested
```

如果不禁止：`f(rawPtr)` 传参时裸指针**悄悄变成** unique_ptr 临时对象，函数返回时临时析构
`delete` 掉——调用者手里的 rawPtr 秒变悬垂，随后双重 delete。**所有权转移这种大事，必须显眼**。

**进阶：explicit 还能修饰转换运算符（你每天都在用它的效果）**——`unique_ptr` 的
`explicit operator bool()`：`if (p)` ✓（条件语境自动用）、`if (!p)` ✓、但 `bool b = p;` ✗。

**人话版**：单参构造函数 = 一扇"从别的类型溜进来"的门；explicit 就是门上贴的
"**请出示证件**"——想进可以，必须明写 `Meters(100.0)`，别想混在 `100.0` 里溜进来。

**记忆钩子**："**单参构造默认上锁（写 explicit），想要门常开才刻意不写**（string 的
`const char*` 构造就是故意开门：`string s = "hi"` 是大家要的便利）。"

**自测**：你 06_ptr.cpp 里 `if (!ptr1)` 能编译，靠的是什么机制？（unique_ptr 的
`explicit operator bool` + 条件语境转换——explicit 只挡"偷偷转"，不挡 if 里的"明知故问"）

【核心规则 **Rule of 3/5/0**】写了析构/拷贝构造/拷贝赋值之一 → 通常五个都要写（Rule of Five）；
更好的是 **Rule of Zero**：用 string/vector/智能指针管资源，五个全不写，编译器合成的自动正确。
（面试第 17 题；CUDA 语境：device buffer 类就该禁拷贝、留移动——见 X01。）

## §C05.3 继承与多态（virtual）

**作用**：派生类复用基类的接口，运行期按"实际类型"选择实现——这就是虚函数。

```cpp
struct Kernel {
    virtual void run() { printf("base run\n"); }   // virtual: 允许派生类重写
    virtual ~Kernel() = default;                   // 基类析构必须 virtual!(面试第 02 题)
};

struct GemmKernel : Kernel {
    void run() override { printf("gemm run\n"); }  // override: 让编译器帮你核对(第 28 题)
};

Kernel* k = new GemmKernel;
k->run();          // 打印 "gemm run" —— 按实际类型分发, 这就是多态
delete k;          // 析构为虚 → 完整销毁
```

【机制】virtual 怎么做到的（vptr/vtable）、性能代价（不可内联/去虚化）、多继承几个 vptr——

## §C05.4 抽象类与接口

**作用**：含纯虚函数的类不能实例化，只作为"接口契约"。

```cpp
struct Op {
    virtual void launch() = 0;      // = 0 纯虚函数: 派生类必须实现
    virtual ~Op() = default;
};
struct GemmOp : Op {
    void launch() override { printf("launch gemm\n"); }
};
// Op o;        // ✗ 编译错: 抽象类不能实例化
Op* o = new GemmOp;  // ✓ 但可以做基类指针
```

## §C05.5 运算符重载

**作用**：让自定义类型支持 `+ - * == <<` 等运算符。

```cpp
struct Vec3 {
    float x = 0, y = 0, z = 0;
    Vec3 operator+(const Vec3& o) const { return {x+o.x, y+o.y, z+o.z}; }
    bool operator==(const Vec3& o) const { return x==o.x && y==o.y && z==o.z; }
};
Vec3 c = a + b;      // 语法糖: 实际是 a.operator+(b)
```

【CUDA 相关】wmma 的 frag 类型、Eigen 的矩阵都靠运算符重载才有 `A * B` 的写法。

## §C05.6 类内 static 与 this 指针

```cpp
struct Counter {
    static int total;                // 所有对象共享一份
    int local = 0;
    void hit() { ++total; ++local; }
    static int report() { return total; }   // 静态成员函数: 无 this, 只能碰静态成员
};
int Counter::total = 0;              // 传统写法: 类外定义 (C++17 可写 static inline int total)
```
