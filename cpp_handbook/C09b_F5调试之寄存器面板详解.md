# C09b F5 调试之寄存器面板详解：CPU 的内脏透视镜

**【前置标注】** C03 §C03.9（内存五区——寄存器是五区之外的"第零区"）；C09 §C09.0（gdb）；
L01 的向量化实验（`<4 x i32>` 落到哪，本文揭晓）。

**【记忆钩子】** r/e 前缀 = **三代家谱**（16位 ax → 32位 eax → 64位 rax），套娃窗口看同一个格子；
面板六个分组 = CPU 的**六个部门**（通用计算/寻址/老浮点/SSE/AVX/化石MMX）。

**【人话版】** 内存（RAM）是仓库，寄存器是 CPU **贴身的口袋**——容量小到只有几十个格子，
但速度比内存快百倍。F5 的 Register 面板就是往这口袋里看的透视镜。看懂它 = 看懂
"变量在机器里真正住哪、参数怎么传、返回值怎么回来"。

---

## 一、先搞懂主角：寄存器是什么

| | 寄存器 | 内存(RAM) | 磁盘 |
|---|---|---|---|
| 容量 | 每个格子 8/16/32/64 位，共几十个 | 几十 GB | TB 级 |
| 速度 | ~0.3ns（和 CPU 同步节拍）| ~100ns（慢300倍）| 毫秒级 |
| C03 对照 | —— | 五区全在内存里（代码区/栈/堆…）| —— |

**所有计算都必须先把数据装进寄存器**——`x++` 的机器码是"把 x 从内存装进寄存器 →
寄存器加一 → 写回内存"。（CUDA 里 GPU 寄存器堆同理，G 系列说的 occupancy/
寄存器 spill 就是 GPU 口袋不够用的故事。）

## 二、r 开头 vs e 开头：三代家谱与套娃

x86 是个 50 年的家族，寄存器名字记录了三代扩容：

| 年代 | CPU | 位宽 | 名字 | 前缀含义 |
|---|---|---|---|---|
| 1978 | 8086 | 16 位 | `ax` `bx` `cx` `dx` | （无前缀）|
| 1985 | 386 | 32 位 | `eax` `ebx` … | **e**xtended（加宽到 32）|
| 2003 | AMD64 | 64 位 | `rax` `rbx` … | **r**egister（加宽到 64）|

**关键认知：rax/eax/ax/al 是同一个物理寄存器的不同宽度"窗口"**（不是四个格子）：

```
0x123456789ABCDEF   ← 64位长面包(实测塞进 rax 的值)
└─ rax  = 0x123456789abcdef   整条
   └─ eax = 0x89abcdef        低32位
      └─ ax  = 0xcdef         低16位
         ├─ al  = 0xef        低8位
         └─ ah  = 0xcd        高8位(只到16位时代)
```

（以上四个值是 gdb 里实测打印的：`set $rax=0x123456789ABCDEF` 后，四个窗口读同一格子。）

**用途**：C++ 的 `int` 运算只用 eax（32位够 int 用）；`long`/指针用 rax；
`uint8_t` 用 al——编译器按需开窗口，**省电省地方**（老代码改低 16 位不动高位）。

## 三、r 开头的一家人：名字有历史分工（含调用约定实测）

| 寄存器 | 名字由来 | 现代职责 | 你在哪见过 |
|---|---|---|---|
| `rax` | Accumulator 累加器 | 算术主力 + **函数返回值放这** | gdb 里函数跑完 print $rax |
| `rbx` | Base 基址 | 任意用途 | |
| `rcx` | Counter 计数器 | 循环计数/移位量 | |
| `rdx` | Data 数据 | 除法余数、64位返回值的高半 | |
| `rsi` | Source Index 源索引 | 串操作源指针 / **第2参数** | |
| `rdi` | Destination 目标索引 | 串操作目标 / **第1参数** | |
| `rsp` | Stack Pointer | **栈顶指针**（C03 的"栈"就是它指的）| 越界检查、栈溢出排查 |
| `rbp` | Base Pointer | 栈帧基址（当前函数栈层的锚）| 面试"栈帧"八股的主角 |
| `r8~r15` | 新增 | 任意用途（第5+参数）| |
| `rip` | Instruction Pointer | **下一条指令地址**（程序计数器）| 断点 = 改写 rip 处的指令 |

### 调用约定（System V AMD64，Linux 通用）——实测验证

参数不是塞包裹里传的，是**按座位坐寄存器**：整数/指针参数依次坐
`rdi → rsi → rdx → rcx → r8 → r9`（第7个起才上栈）；**浮点参数坐 xmm0~**；
返回值回 `rax`。实测（`add3(11,22,33)` 断点处）：

```
(gdb) break add3 && run
(gdb) print $rdi    → 11   ← 第1参数
(gdb) print $rsi    → 22   ← 第2参数
(gdb) print $edx    → 33   ← 第3参数(edx 是 rdx 的 32 位窗口——int 只需 32 位)
```

**人话版**：函数调用像递东西——前六件放进六个贴身口袋（寄存器），第七件才打包上栈。
这就是"传参开销小、参数太多变慢"的底层原因（也解释了 CUDA 里 kernel 参数走 constant
memory 的对照设计）。

## 四、面板六个分组：六个部门（含历史化石）

### CPU 组
上面的通用寄存器 + rip + eflags（标志位：上次运算的零/负/进位——if/循环跳转的依据）。

### Segs 组（段寄存器：历史包袱 + 一个活着的）
`cs ds ss es fs gs`——1978 年 8086 用"段:偏移"拼 20 位地址的遗产，现代几乎退休，
**唯一重任：fs/gs 存线程本地存储(TLS)的基址**——每个线程的"专属抽屉"地址，
`std::this_thread`、`thread_local` 变量全靠它找到自己的那份。**和 C09 直接相关**：
两个线程的 fs 值不同 = 它们看同一个 `thread_local` 变量却各拿各的。

### FPU 组（x87：1980 年代的浮点老店）
`st0~st7`——八层**栈式**浮点寄存器（怪癖：算浮点像摞盘子）。现代编译器的
float/double **不走这**（走 SSE），只在编译 32 位老代码或 long double 时露面。
看到它只需认识，不用深究。

### SSE 组（xmm0~xmm15：128 位，**你的 float 真正的家**）
`float`/`double` 的标量运算、SIMD 向量全在这。实测：`fscale(3.5f)` 断点处

```
(gdb) print $xmm0
→ {v4_float = {3.5, 0, 0, 0}, ...}     ← 128 位格子按 4 个 float 车道看,
                                          3.5 躺在第一车道
```

**L01 的重逢**：opt -O2 生成的 `<4 x i32>`、`<8 x float>` 向量指令，最终就是落到
xmm/ymm 上执行的——当时你看到的 IR 向量化，硬件落点就在这个面板里。

### AVX 组（ymm0~ymm15：256 位，SSE 的加宽版）
ymm 是 **xmm 的套娃父亲**（ymm 的低 128 位就是 xmm——又是家谱！）。`<8 x float>`
一条 AVX 指令伺候。再往新还有 AVX-512（zmm，512 位），你 4060 的 CPU 面板不一定有。

### MMX 组（mm0~mm7：1996 年的化石）
第一代 SIMD，64 位，**和 FPU 的 st0~st7 共用同一块物理电路**（当年为了不增加晶体管），
导致混用会互相污染——设计缺陷加上 64 位太窄，被 SSE 取代。现代代码零使用，
面板里出现纯属"博物馆展品"。

## 六、自测题

1. `print $rax` 是 0x123456789ABCDEF，那 `print $eax` 显示什么？（0x89abcdef——低 32 位窗口）
2. `f(int, int, float, int)` 四个参数分别坐哪？（rdi, rsi, **xmm0**, edx——浮点单独走 SSE 通道）
3. 为什么 `uint8_t` 加法可能只动 al 不动 eax 其余位？（窗口够窄就开窄窗——历史兼容设计）
4. 你的 triton kernel 里一个 thread 有多少寄存器可用？（CUDA 最多 255 个/线程——GPU 口袋更大但也要省着用，spill 到 local memory 就慢了——occupancy 的另一半故事）

动手：`g++ -g 你的.cpp && gdb ./a.out`，break 到任意函数，把本文的每条 print 命令跑一遍。
