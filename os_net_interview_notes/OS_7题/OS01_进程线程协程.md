# OS-01 进程 / 线程 / 协程：区别与切换成本

## 面试口述版

三者是"隔离程度递减、切换成本递减"的三个层次：
**进程** = 独立地址空间 + 独立资源，隔离最强；创建要 fork（复制页表/COW 设置）、切换要换页表（TLB 受影响），都贵。
（**COW** = Copy-On-Write 写时复制：fork 时并不真复制内存，而是父子共享物理页并标记只读，
谁先**写**谁才触发缺页、拿到自己的私有副本——"先假装一样，写的时候才分家"。）
**线程** = 同一地址空间里的执行流；创建只分配栈+调度对象（微秒级），切换不用换地址空间（快），共享数据零拷贝但要自己加锁。
**协程** = 用户态自己调度的"轻线程"：切换就是保存/恢复几个寄存器+栈指针（几十 ns），不进内核、不被内核感知——代价是阻塞式系统调用会卡住整个宿主线程。
成本量级（本机 WSL 实测见 demo）：线程创建 ~100μs、fork ~240μs（2-3 倍差）、yield 乒乓切换几百 ns~几 μs、协程切换 ~几十 ns。

## 高频追问

- **上下文切换到底切什么？** 寄存器组 + 内核栈 + 调度信息；跨 CPU 核迁移还要付出缓存/TLB 变冷的隐性成本——所以"进程绑核"在高性能场景常见。
- **为什么 fork 后地址"一样"却不冲突？** 写时复制（COW）：页表复制但页标记只读，谁先写谁触发缺页拿私有副本——和 IPC 的共享内存是两个方向。
- **GPU 联动**：CUDA 上下文绑定进程；host 端工作线程池选线程不选 fork（要共享 context）；NCCL 单机多卡共享一个进程的 context，跨卡通信靠 SM 间 DMA 而非进程间。

## 记忆钩子

"进程换房子，线程换岗位，协程换姿势；越往后越便宜，隔离也越少。"

**人话版**：三个比喻对应三种隔离级别——**进程** = 搬进一套新房子（独立地址空间，互不干扰但搬家
费劲：要复制页表，切换还要换整套地址映射）；**线程** = 同一套房子里换个干活的人（共享内存和家具，
创建切换都便宜，但要自己加锁防打架）；**协程** = 同一个人在几件事之间切换姿势（用户态自己调度，
几十纳秒切一次，最便宜，但一个协程卡在系统调用里全屋都得等）。
