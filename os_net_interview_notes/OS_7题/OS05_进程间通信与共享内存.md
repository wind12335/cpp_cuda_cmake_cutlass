# OS-05 进程间通信：重点讲共享内存（NCCL 单机通信的底座）

## 面试口述版

IPC 谱系按"数据搬运次数"排：**管道/消息队列**——数据走内核中转（用户→内核→用户，两次拷贝 + 两次系统调用每块）；
**共享内存**——两个进程把**同一批物理页**映射进各自地址空间，数据零拷贝、零系统调用，
代价是"同步要自己管"（需要信号量/原子旗标配合）；**socket（本机回环）**——还要过完整协议栈，最慢；
**信号/事件通知**——只传信号不传数据。
量级实测（本机 demo）：管道 1.2 GB/s vs 共享内存 ~100 GB/s，**差 80 倍**。
**NCCL 的对应关系**（你最能打的一张牌）：单机内两卡直连走 NVLink P2P（DMA 直达，绕过 CPU）；
**不支持 P2P 的组合（混插卡/老平台）退化为 SHM transport——就是经 host 内存的共享内存方案**；
跨机才走 IB/RoCE。所以面试聊"NCCL 为什么快"，能落到"P2P 直达 / SHM 零拷贝 / socket 兜底"三层机制，
比背 API 高一个档次。

## 高频追问

- **共享内存的同步怎么做？** 信号量（sem_init 设 pshared）/ 文件锁 / 进程间共享的 atomic（放共享页里，配 acquire/release）——demo 里就是共享页上放原子旗标。
- **匿名 mmap vs shm_open？** 父子进程用 `MAP_ANONYMOUS|MAP_SHARED`（fork 继承映射）最简单；无亲缘关系的进程用 `shm_open + ftruncate + mmap`（落在 /dev/shm）。
- **为什么管道慢？** 每块数据两次拷贝（进内核缓冲、出内核缓冲）+ 读写各一次系统调用陷入——联动 OS-06 的陷入成本。

## 动手绑定

`demos/os5_shm_ipc.c`：父子进程分别用管道和共享内存搬 512MB，带宽数倍差一目了然。

```bash
g++ -O2 -pthread demos/os5_shm_ipc.c -o /tmp/os5 && /tmp/os5
# 实测: pipe ~1.2 GB/s vs shm ~100 GB/s
```

## 记忆钩子

"管道两拷贝两陷入，共享内存零拷贝自己管同步；NCCL 单机兜底走的就是这套 shm。"

**人话版**：**管道**传数据要过两次手（用户→内核→对方用户），每块数据还要各一次系统调用
（"陷入"= 进入内核），实测 1.2 GB/s；**共享内存** = 两个进程把同一块物理内存映射进各自地址空间，
数据原地不动、直接可见（零拷贝，实测 100 GB/s），代价是"谁写完了"要自己用信号量/原子旗标管。
NCCL 在两张卡之间没有 P2P 直连通道时，退化的 SHM 传输方案底层就是这套机制。
