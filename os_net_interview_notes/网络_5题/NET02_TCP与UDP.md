# NET-02 TCP vs UDP

## 面试口述版

**TCP**：面向连接的**字节流**——可靠（确认+重传）、有序（序号排序）、拥塞控制（不压垮网络）、流量控制（滑动窗口）；
头部 20B 起，代价是延迟和协议栈开销。
**UDP**：无连接的**数据报**——不保证送达/有序/不拥塞控制，头部仅 8B，发出去就不管，快而裸。
选择标准：**要"一定到、按序到"用 TCP**（HTTP/RPC/训练参数下发）；**要"快、容忍丢"用 UDP**
（视频会议、游戏、DNS）；**要"既快又可靠"把可靠性下沉到硬件/应用层**——RDMA/RoCE 就是把可靠传输
做进网卡绕过内核协议栈，QUIC 则在 UDP 上用户态重建可靠性。
本机 demo 实测回环：TCP 吞吐可达 GB/s 级、1 字节 RTT 百微秒级（WSL 虚拟化偏高，裸机几十微秒）、
UDP 每秒 8.6 万包 1KB 数据报；UDP 高速灌包时会看到真丢包——"不可靠"是特性不是缺陷。

## 高频追问

- **TCP 粘包是什么？** 字节流没有"包"的概念，两次 send 的数据可能一次 recv 出来——是应用层没定义消息边界的问题，解法：定长/分隔符/长度前缀。
- **UDP 怎么做到可靠？** 应用层自己加序号/确认/重传（KCP/QUIC/RDMA 的思路）——按需定制比 TCP 的通用重传更省延迟。
- **NCCL 用哪个？** 跨机走 RDMA（RoCE 是 UDP 直接数据放置 + 硬件可靠层）或 IB；某些云上 TCP 兜底——集合通信的带宽敏感特性决定了"越靠近裸网络越好"。

## 动手绑定

```bash
g++ -O2 -pthread demos/net2_tcp_vs_udp.c -o /tmp/net2 && /tmp/net2
# 注: WSL2 回环偏慢(吞吐/RTT 都虚高), 裸机上 TCP 回环常见 5-20 GB/s、RTT 几十微秒
```

## 记忆钩子

"TCP 是挂号信（慢而必达），UDP 是扔纸飞机（快而看命）；又快又可靠？把可靠性焊进网卡（RDMA）。"

**人话版**：**TCP** 发出去的每包都有确认和重传、按序送达（挂号信），代价是协议栈处理延迟；
**UDP** 发出去就不管了（纸飞机），快但可能丢、可能乱序。两者都有时不够用——要"既快又可靠"就把
可靠性从软件挪进**网卡硬件**（RDMA：网卡自己保证送达，绕过整个内核协议栈），NCCL 跨机通信走
的就是这条路。
