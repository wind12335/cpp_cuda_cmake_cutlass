# K01 最小工程与构建流程 【基础】

## §K01.1 CMake 是什么

**作用**：C++ 项目的"构建脚本生成器"。手写 g++ 命令在几个文件时可行，几十个文件、
CUDA 语言、第三方依赖一多就不可维护——CMakeLists.txt 用**声明式**描述"我要构建什么、
依赖什么"，CMake 负责生成对应平台的构建系统（Makefile/Ninja），再由它调用 g++/nvcc。

```
CMakeLists.txt (你写的, 平台无关)
     │ cmake -B build          ← 配置阶段: 探测编译器/依赖, 生成构建文件
     ▼
build/ (Makefile 等生成物)
     │ cmake --build build     ← 编译阶段: 真正调用 g++/nvcc
     ▼
可执行文件 / 库
```

【为什么 CUDA 学习者必须会】LeetCUDA、vLLM、所有 GPU 工程都用 CMake 管理；
面试聊"你的 kernel 怎么编译"就是聊 CMake。

## §K01.2 最小工程逐行精读

```cmake
cmake_minimum_required(VERSION 3.18)     # ① 声明"我至少需要这个版本的 CMake"
                                         #   永远放第一行; 版本决定行为兼容模式
project(hello_cpp                        # ② 项目名
        LANGUAGES CXX)                   #   启用哪些语言(CXX=C++; CUDA 工程要加 CUDA)

add_executable(hello main.cpp)           # ③ 声明一个"目标": 从 main.cpp 编出可执行文件 hello
```

| 行 | 常见错误 |
|----|---------|
| ① 不写 | 新版 CMake 会警告甚至拒绝配置 |
| ② LANGUAGES 忘了 CUDA | .cu 文件不被 nvcc 处理 |
| ③ 目标名和输出名 | 目标名 = 产物名（可后续改名，但初学保持一致） |

## §K01.3 标准构建流程（三板斧）

```bash
cd 01_hello_cpp
cmake -B build -DCMAKE_BUILD_TYPE=Release   # ① 配置(生成 build/ 目录)
cmake --build build -j8                     # ② 编译(-j8 = 8 线程并行)
./build/hello                               # ③ 运行
```

- **out-of-source 构建**：生成物全在 build/ 里，源码目录永远干净；删掉 build/ = 彻底重来；
- 改了 CMakeLists.txt 后不用手动重新配置——`cmake --build` 会自动重新生成；
- 【坑】在源码目录直接 `cmake .`（in-source 构建）会把生成物撒进源码目录，删都删不干净——
  已经踩了就 `rm -rf CMakeCache.txt CMakeFiles/` 清理。

## §K01.4 构建类型：Debug / Release 【新手 benchmark 头号大坑】

**作用**：一键切换编译优化级别。

| 类型 | 编译参数 | 什么时候用 |
|------|---------|-----------|
| 空（默认！） | **无优化** | ⚠ 不指定时的状态——测性能纯属自欺 |
| Debug | `-g` | gdb 调试/断点 |
| Release | `-O3 -DNDEBUG` | **日常开发与 benchmark 的标准选择** |
| RelWithDebInfo | `-O2 -g` | 要性能也要能看调用栈 |

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release    # ← 记住这行
```

【实测意义】你在 CUDA 手册里所有 TFLOPS 数字都默认以 Release 心态测的——如果 host 代码
无优化，数据准备阶段反而可能成为瓶颈。
