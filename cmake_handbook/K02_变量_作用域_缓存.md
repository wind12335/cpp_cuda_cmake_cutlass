# K02 变量、作用域与缓存 【基础】

## §K02.1 set 与变量引用

**作用**：CMake 变量就是"字符串名 → 值"的映射，用于集中管理配置。

```cmake
set(APP_NAME gemm_demo)                 # 定义变量
set(SRC main.cu kernel.cu)              # 值可以是列表(空格分隔)

add_executable(${APP_NAME} ${SRC})      # ${变量名} 取值 —— 和 shell 一个感觉
```

【前置：K01.3】变量在**当前目录及其子目录**生效（add_subdirectory 的子目录继承父目录的变量，
反向不可见——这是"作用域"规则）。

## §K02.2 常用内置变量

| 变量 | 含义 | 你会用到的场景 |
|------|------|---------------|
| `CMAKE_BUILD_TYPE` | 构建类型（空/Debug/Release…） | **必设 Release 测性能** |
| `CMAKE_CUDA_ARCHITECTURES` | GPU 架构号（86/89/90…） | CUDA 工程必设（4060=89） |
| `CMAKE_CUDA_COMPILER` | nvcc 路径 | 多版本 CUDA 切换 |
| `PROJECT_SOURCE_DIR` | 项目根目录绝对路径 | 拼 include/资源路径 |
| `CMAKE_CXX_STANDARD` | C++ 标准（17/20） | `set(CMAKE_CXX_STANDARD 17)` |

```cmake
set(CMAKE_CXX_STANDARD 17)              # 全工程 C++17 (等价每个 target 加 -std=c++17)
set(CMAKE_CXX_STANDARD_REQUIRED ON)     # 编译器不支持就报错(而不是静默降级)
```

## §K02.3 option：用户可开关的开关

**作用**：给工程加"编译期开关"，命令行可控制。

```cmake
option(USE_FP16 "用 fp16 而不是 fp32" ON)      # 第三个参数是默认值

if (USE_FP16)
    target_compile_definitions(gemm PRIVATE USE_FP16)   # 给代码注入宏 USE_FP16
endif()
```

```bash
cmake -B build -DUSE_FP16=OFF          # 命令行覆盖开关
# 代码里: #ifdef USE_FP16 → 走 fp16 路径, 否则 fp32
```

【CUDA 相关】LeetCUDA 式工程常用 option 控制要不要编某些 kernel 变体——
"一份源码，多种精度配置"的机制基础。

## §K02.4 缓存变量：跨配置持久的变量

**作用**：普通 set 变量只在一次配置中有效；**cache 变量**存在 build/CMakeCache.txt 里，
跨配置持久，且能在命令行用 `-D` 覆盖。

```cmake
set(MY_ARCH 89 CACHE STRING "GPU 架构")     # CACHE: 变成缓存变量
# 命令行: cmake -B build -DMY_ARCH=86       # 用户可覆盖
```

其实 `CMAKE_BUILD_TYPE`、`CMAKE_CUDA_ARCHITECTURES` 就是内置的缓存变量——
所以能用 `-D` 从命令行设置它们。
