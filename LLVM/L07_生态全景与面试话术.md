## 一、Triton 编译栈全链路（面试必考，你的最大筹码）

你写过 Triton（LeetCUDA），现在补"它怎么编译你"：

```
你写的 @triton.jit 函数（Python AST）
   ↓  前端：解析 Python → MLIR
TTIR   (Triton IR，block 级：一个 program 处理一块数据，天然并行)
   ↓  TTIROps → TTGIR 转换（做布局/分配）
TTGIR  (Triton GPU IR，线程级：哪个线程搬哪块数据、寄存器怎么摆)
   ↓  convert 到 LLVM dialect
LLVM IR
   ↓  LLVM NVPTX 后端
PTX → ptxas → SASS  ← 你 CUDA 手册 G 系列的老朋友
```

**每一站对应你的已有知识**：

| 编译站 | 你的对应物 |
|---|---|
| TTIR 的 program/block 概念 | kernel grid/block 划分（`tl.program_id` 你天天用） |
| TTGIR 的线程布局 | 你手动摆的 `blockIdx/threadIdx` + shared memory 分配 |
| PTX/SASS | G07 你看过的 mma 指令流 |
| `@triton.autotune` | L06 的 tile-sizes 搜索（自动调优） |
| num_warps/BLOCK_SIZE 参数 | tiling + 并行度切分 |

**面试一句话**："我写过 Triton 算子也懂它的编译链路——TTIR 是 block 级的 MLIR 方言，下降到 TTGIR 做线程级布局，再过 LLVM 出 PTX。autotune 本质是 tile 参数搜索，我在 4060 上实测过不同 BLOCK 的性能差异。"——这一句就把 90% 只会"用"的竞争者甩开了。

## 二、各家编译栈站位图

| 编译器 | 东家 | IR/路线 | 一句话 |
|---|---|---|---|
| **TorchInductor** | Meta（PyTorch 官方） | torch FX 图 → 自定义 Triton 代码生成（GPU）/ C++（CPU） | `torch.compile` 默认引擎；GPU 算子直接**生成 Triton 代码** |
| **XLA** | 谷歌 | HLO（先于 MLIR 的稳定图 IR）→ 各后端 | TPU 御用；GSPMD 并行切分是其名场面 |
| **TVM** | 社区（Apache） | Relay/Relax 图 IR + TE tensor 表达式 → tir | 老牌；auto-tuning（Ansor/MetaSchedule）是招牌 |
| **IREE** | 社区（谷歌发起） | **纯 MLIR 路线**：linalg/vector 一路降到底 | MLIR 编译器的标杆实现，读它的流水线=读 MLIR 应用论文 |
| **MLIR** | LLVM 基金会 | 基础框架 | 上面各位的公共底座（除 XLA/TVM 的自研 IR 部分） |

**关系口诀**：MLIR 是地基，IREE 是全 MLIR 盖的样板房，Triton/Inductor 借了半层（用 MLIR 做中段），XLA/TVM 自持地皮但都通了 MLIR 的路。

## 四、国产 GPU 编译栈（差异化武器）

海光（DCU/ROCm 系）、寒武纪、昇腾、沐曦、摩尔线程……全员在自建/改造编译栈，且几乎都绕开 CUDA：

- ROCm 系（海光兼容路线）：HIP + MLIR 化的编译组件（comgr/hipify）
- 昇腾：CANN 的图编译（类似 XLA 思路）+ 张量算子 TBE
- MLIR 已是国产芯片编译器的**事实公共底座**（对标"绕开 CUDA 但不重造轮子"）

为什么都选 MLIR？——L02 讲过：**自定义 dialect 零侵入**。新硬件只需定义自己的"硬件方言"（描述寄存器/cluster/特殊指令），复用整个优化/下降框架。**"为国产 GPU 定义 dialect + lowering"就是这类公司编译器岗的日常工作**——现在你知道 JD 里"MLIR+Linalg 框架"为什么是硬性要求了。

## 五、面试问题预测（按概率排序）

1. **"讲讲 MLIR 的核心概念"**——Operation 一切皆/Region-Block 树/dialect 方言/多层下降通 LLVM（L02 的钩子直接用）。
