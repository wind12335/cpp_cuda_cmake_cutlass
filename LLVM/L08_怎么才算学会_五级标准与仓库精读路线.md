## 二、你已学的知识和 MLIR/LLVM 的关系（关系地图）

**总纲一句话**：C++/CMake 是**工具层**（两边共用）；CUDA/CUTLASS 是**答案层**（你手动做出最优算子）；MLIR/Linalg 是**生成层**（让机器自动生成你手动做的东西）；Triton 是你已经用了一年的 **MLIR 应用**（你写前端，它编译）。

### 2.1 C++ ↔ MLIR/LLVM：MLIR 本体就是 C++ 写的

| 你学过的（cpp_handbook） | 在 MLIR 里的化身 |
|---|---|
| CRTP 奇异递归模板（C02.4） | `PassWrapper<我的Pass, ...>` 就是 CRTP——你写 L04 时已经用了一次 |
| unique_ptr 工厂（C02.6） | `CreatePrintOpNamesPass()` 返回 `unique_ptr<Pass>`，一模一样的套路 |
| static 四用法之"全局对象构造先于 main"（C02） | `PassPipelineRegistration` 全局变量注册 Pass——就是靠这个 |
| 虚函数表/多态（C02.4） | `runOnOperation()` override——引擎拿着基类指针调你 |
| -fno-rtti（C02 提过 RTTI 开销） | MLIR/LLVM 全库关 RTTI，我们的 CMakeLists 里 `add_compile_options(-fno-rtti)` |

### 2.2 CMake ↔ MLIR：out-of-tree Pass 工程就是普通 CMake 工程

| 你学过的（cmake_handbook） | 在 LLVM lab 里的化身 |
|---|---|
| find_package(CUDAToolkit) + CUDA::cudart（K03/K04） | find_package(MLIR) + MLIRPass 等 imported target——**同一套机制** |
| target_link_libraries PUBLIC/PRIVATE | labs 里 PRIVATE 链库 |
| 报错"needs to be enabled"排查思路 | `project(x C CXX)` 两语言声明（L04 坑1） |

**结论**：你的 CMake 功底在编译器方向无缝复用——岗位 JD 里"CMake 熟悉"这条你已经有了。

### 2.3 CUDA ↔ MLIR：你的手动优化 = 编译器要自动生成的目标

| 你学过的（cuda/cutlass_handbook） | MLIR 对应物 | 在哪见过 |
|---|---|---|
| 合并访存/内存层级（G03/G04） | memref 的布局 `#map`（affine_map 线性化索引）；bufferize 插的 `alignment=128` | L06 实测 |
| reduce 六级阶梯（G05） | 渐进 lowering：一层 Pass 降一级 | L01 opt 的 O0→O2 |
| 双流重叠（G06） | 调度类变换（GPU 后端 async/pass 化） | 概念对应 |
| **CUTLASS GemmShape<128,128,32>** | **`--linalg-tile="tile-sizes=128,128,32"`** | L06 重磅实验 |
| CUTLASS epilogue 融合（08 篇） | linalg 算子融合（迭代空间共享） | L06 第五节 |
| CUTLASS Layout/TensorRef 坐标→偏移 | memref subview 的 stride/offset 映射 | L06 坑3 |
| wmma/mma（G07） | vector dialect 的 mma 类 op → NVVM → PTX | L07 第 1 节 |
| ncu/nsys 调优 | `--mlir-print-ir-after-all` 看每站变换 | L03 |

**还有个冷知识**：你编译的每个 CUDA kernel 最后都过 **LLVM 的 NVPTX 后端**出 PTX。你以为没碰过 LLVM，其实它一直在你工具链的最后一站。

### 2.4 Triton ↔ MLIR：你已经是 MLIR 的"用户"，现在去看引擎盖下面

你写 LeetCUDA 时干的事在编译栈里的位置：

```
你写的 @triton.jit（Python）        ← 你熟（前端）
        ↓
TTIR（block 级 MLIR 方言）           ← tl.program_id 你天天用，它就活在这层
        ↓
TTGIR（线程级：谁搬哪块数据）          ← 对应你手摆的 threadIdx/共享内存
        ↓
LLVM IR → PTX → SASS                 ← 你 G 系列看过的底层
```

- `BLOCK_SIZE`/`num_warps` 参数 = tiling/布局参数（L06 的 tile-sizes）
- `@triton.autotune` = tile 参数搜索（自动调优）
- **所以学 MLIR 不是"多学一门新技术"，是"给你用了一年的东西补上原理课"**——面试讲 Triton 你就比别人深一层。

### 2.5 一张总图

```
工具层：   C++ ──── CMake ──── pybind11
             │         │
答案层：   CUDA ── CUTLASS ──（你已掌握：手动做出最优算子）
             │         │
生成层：   LLVM IR ── MLIR ── Linalg ──（本手册：让机器自动生成上面那些）
             │         │
应用层：   Triton ── TorchInductor ── IREE ──（你用过的前端/框架）
```

学习顺序上你是**自底向上倒着爬**（先答案层后生成层），好处是编译器每个 lowering 的"终点"你都亲手写过——这正是编译器岗最稀缺的背景。

## 三、Level 4 精读路线：两个本地仓库怎么用

### 3.0 版本说明（重要，别踩晕）

| 目录 | 是什么 | 怎么用 |
|---|---|---|
| `llvm-project/` | main 分支浅克隆（最新版） | **读**——看最新 API 长什么样（如 Arith 新目录名） |
| `llvm-project-15/` | release/15.x 分支 | **对着本机 MLIR 15.0.7 读+跑 tblgen**——版本一致才不精神分裂 |
| `buddy-mlir/` | 北航教材仓库 | 读 examples，中文注释友好 |

### 3.1 第一站：TestPrintDefUse（我们 L04 的"官方满血版"）

```
llvm-project/mlir/test/lib/IR/TestPrintDefUse.cpp
```

精读任务：找出它比我们 L04 多打印了什么（**def-use 链**：每个值是谁定义的、被谁用了）。读完你能回答：`%1` 这个 Value，怎么遍历它的所有使用者？（`value.getUsers()`——这是写融合 Pass 的基本功：找 producer 的 consumer 才能融合。）

### 3.2 第二站：toy Ch2 —— 一个方言是怎么"定义"出来的

```
llvm-project-15/mlir/examples/toy/Ch2/
├── include/toy/Ops.td       ← 重点①：TableGen 定义（"声明式"的极致）
├── include/toy/Dialect.h    ← 重点②：方言类的 C++ 壳
├── mlir/Dialect.cpp         ← 重点③：注册
├── mlir/MLIRGen.cpp         ← AST→MLIR 翻译（前端怎么做）
└── parser/AST.cpp           ← 词法语法（可跳过）
```

**动手**（版本对齐后可用，本机已装 mlir-tblgen）：

```bash
/usr/lib/llvm-15/bin/mlir-tblgen --gen-op-defs \
  llvm-project-15/mlir/examples/toy/Ch2/include/toy/Ops.td \
  -I llvm-project-15/mlir/include/ | head -40
```

看 TableGen 把 30 行 `.td` 展开成几百行 C++（op 类、parser/printer、验证器全是生成的）——**读 .td 是读"设计"，读生成物是读"实现"**。

精读问题：`toy.transpose` 在 .td 里几行？生成的 C++ 多少行？（体会：MLIR 把样板代码成本降到接近零——这就是"自定义方言零侵入"的 mechanically 实现。）

### 3.3 第三站：toy Ch3 —— DRR：把 L05 手写的 Pattern 变成声明式

```
llvm-project-15/mlir/examples/toy/Ch3/mlir/ToyCombine.td
```

对照读：你在 L05 手写的 `addf %x,%x → mulf %x,2`，在 DRR 里是类似：

```
def AddSelfToMul : Pat<(ToyAddOp $x, $x), (ToyMulOp $x, (ConstantTwo))>;
```

一行 = 你那 25 行 C++。**先手写后读 DRR 才能懂 DRR 生成了什么**——顺序不能反，这也是为什么 L05 必须手写。

### 3.4 第四站：buddy-mlir 的 BudDialect（完整最小示例）

```
buddy-mlir/examples/BudDialect/
```

一个能编译运行的最小自定义方言工程（bud-opt 等）。**读它的 CMakeLists 怎么写**——照着它，你就能给自己的研究方向定义方言（比如一个表达"通信算子"的 dialect——和你 overlap 课题直接挂钩，L07 第三节）。

### 3.5 第五站（选，对接岗位）：BuddyMatmul / BuddyGPU

matmul 从 MLIR 降到 GPU 的完整例子，串你的 CUTLASS 背景。到这站你已经在读"生产级"代码了。

### 3.6 ⚠️ 诚实边界（本机不能干什么）

- **不要在本机 build llvm-project / toy / buddy**（7.6G 内存必 OOM/跑通宵）。读代码 + 跑 mlir-tblgen（轻量）没问题；要真编译，租 32G 内存的云主机（那时照着 toy 的 README 走即可）。
- toy 的 `toyc` 编译器本机跑不了 → **Level 4 的"写得出"用我们 labs 的骨架完成**（见 3.7）。

### 3.7 Level 4 的毕业设计：mini-canonicalize

不抄 toy，在 `05_rewrite_pass` 基础上扩一个**你自己的规则库**，凑齐 5 条规则：

1. ☐ `muli %x, 1 → %x`（整数乘一，L5 自测1）
2. ☐ `addi %x, 0 → %x`（整数加零）
3. ☐ `addf %x, %x → mulf %x, 2.0`（已有）
4. ☐ `muli (muli %x, c1), c2 → muli %x, c1*c2`（常量折叠——要用 `matchAndRewrite` 里判断操作数是否 ConstantOp，练 op 向上查 def）
5. ☐ 自选一条（比如 `subf %x, %x → 0.0`？想清楚浮点安全性再动手！）

验收：写一个 20 行的 test.mlir 把五种模式全埋进去，`--my-canonicalize` 一把全化简。**做完这个，"你写过 MLIR Pass"这句话在面试里就有 20 分钟可讲**（规则设计、安全性判断、引擎机制、和官方 canonicalize 的差异都能聊）。
