# G08 调试与性能工具 【工具】

> "写完了"和"写对了/写快了"之间隔着一整套工具链。本篇是`cuda_interview_notes/4060_可学清单.md` ncu 入门的理论底座。

## §G08.1 kernel 内 printf（最快但最糙）

```cuda
__global__ void k() {
    if (blockIdx.x == 0 && threadIdx.x == 0)   // 限定输出量, 否则刷屏
        printf("hello from block 0\n");        // device 端 printf, 输出到 host stdout
}
```

限制：输出有缓冲（结尾要 `cudaDeviceSynchronize` 才刷新）、顺序不保证、**严重拖慢 kernel**——只用于调试。

## §G08.2 compute-sanitizer：正确性工具

**作用**：抓内存越界、竞争、未初始化——错误码查不出的逻辑炸点。

```bash
compute-sanitizer --tool memcheck  ./app     # 越界/非法访问(报告精确到行)
compute-sanitizer --tool racecheck ./app     # shared memory 竞争(含 bank conflict 相关)
compute-sanitizer --tool initcheck ./app     # 未初始化读
```

慢 10-50 倍——**调试工具不是性能工具**。建议：每个新 kernel 都跑一遍 memcheck 再谈性能。

## §G08.3 nsys：系统时间线 【先粗】

**作用**：回答"时间花在哪、有没有空隙、多流是否真的并发"。

```bash
nsys profile -o out --force-overwrite true ./app
nsys stats out.nsys-rep                  # CLI 出统计表(无 GUI 环境用这个)
nsys-ui out.nsys-rep                     # 有 GUI 时打开时间线
```

看什么：kernel 之间的 gap（CPU 喂不上）、memcpy 占比（搬运瓶颈）、多个流的条带是否**并行**
（重叠是否成立——你论文实验的核心图）。

## §G08.4 ncu：单 kernel 显微镜 【后细】

**作用**：钻进一个 kernel 回答"它为什么慢"。

```bash
ncu --set basic  -k "regex:kernel名" ./app     # 快扫: SOL 两率
ncu --set full   -o prof -f ./app              # 全量(慢, 采集到文件)
ncu --page details --csv ./app > out.csv       # 无 GUI 导出
```

看什么（顺序）：① SOL 页 `SM %` 与 `Memory %` —— 谁高谁是瓶颈（roofline 定位，前置：面试 G19）；
② Occupancy 页的限制因素；③ Warp State 的 top stall（`long scoreboard` = 等显存）；
④ Memory Workload 的事务放大/bank conflict。

【铁律】ncu 会重放 kernel，**绝对时间不可信，比例与计数器可信**——绝对时间用 event/nsys。
【WSL】先解锁权限（Windows 控制面板 → 管理 GPU 性能计数器），否则 ERR_NVGPUCTRPERM。

## §G08.5 nvcc 编译 flag 与性能

| flag | 用途 |
|------|------|
| `-Xptxas -v` | 打印寄存器/shared 用量（判断寄存器压力第一工具） |
| `-lineinfo` / `-g` | ncu 里看到源码行 |
| `-use_fast_math` | 换快速数学近似（精度下降，推理可用训练慎用） |
| `-maxrregcount=N` | 压寄存器上限（通常用 launch_bounds 更好） |
| `-G` | 完全不优化（只用于调试） |

## §G08.6 工作流总结

```
跑通(memcheck) → nsys 看全局(找最大耗时 kernel / 找空隙) → ncu 钻那个 kernel
→ SOL 定位访存还是计算受限 → 对症优化 → event/nsys 复测对比 → 循环
```
