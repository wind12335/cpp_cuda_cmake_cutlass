## §6.2 台阶②：定制 epilogue（最实用的进阶）

LLM 推理的 GEMM 后面总跟着 `+bias → 激活`——CUTLASS 把这做成 **Epilogue Functor**：

```cpp
// LinearCombination 换成 LinCombPerRowBiasL2NormBinaryOp 系列 predefined functor,
// 或者自己写一个 EpilogueVisitor: 对每个输出元素做 C = act(alpha*A*B + bias[j])
```

入口：`include/cutlass/epilogue/thread/` 目录（几十个现成 functor）+
官方例子 `12_gemm_bias_relu`（read + 跑通 + 改成 GELU）。
【前置：G09 速查——LeetCUDA 的 `12_gemm_bias_relu` 对应物是你早就会的"算子融合"思想】

## §6.3 台阶③：3.x/4.x Collective API（通往 Hopper/Blackwell）

2.x 风格 device::Gemm 到 Sm80 为止（LabB 的 Sm80 标签即此原因）。**Sm90 (H100) 的 WGMMA/TMA、
Sm100 (Blackwell) 的新一代特性，必须用 3.x CollectiveBuilder**：

```cpp
using CollectiveMainloop = typename cutlass::gemm::collective::CollectiveBuilder<
    cutlass::arch::Sm90, cutlass::arch::OpClassTensorOp,   // H100
    ...>::CollectiveOp;
```

入口：`examples/70_blackwell_gemm`、`examples/6x_...` 系列（本地 4.6.1 都有）。
你现在不用深入，知道"新架构 = 新 API 代际"即可——租到 H100 后这就是你的第一课。

## §6.4 Split-K 与 Stream-K（调度策略，和你课题沾边）

- **Split-K**：把 K 维切开让更多 block 参与计算（小 M/N 大 K 时并行度不足的救星），
  代价是需要"部分和归约"——**和你 overlap 课题里的多卡规约同构**；
- **Stream-K**（CUTLASS 3.x）：块间负载不均的更优雅解法。
  入口：`examples/06_splitK_gemm`、`examples/48_...` 系列。
