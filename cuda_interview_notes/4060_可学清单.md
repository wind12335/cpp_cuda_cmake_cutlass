# LeetCUDA 4060 单卡可学清单（2026-09 侦察结果）

> 原则：单卡 sm_89 能跑的马上学；需要 Hopper/多卡的记入"云平台清单"，等租卡再做。

## Tier 1 — ncu 正式上手（你点名要学的，最优先）

**第 0 步：解锁 WSL 的 ncu 权限（一次性）**
本机 `ncu` 目前报 `ERR_NVGPUCTRPERM`——WSL 下 GPU 性能计数器默认关闭。修复：
1. 回到 **Windows**，打开 NVIDIA Control Panel（NVIDIA 控制面板）
2. 菜单栏 → **桌面**（或"开发人员"菜单）→ 勾选**开发人员选项**后可见
   **"管理 GPU 性能计数器"（Manage GPU Performance Counters）**
3. 选 **"允许访问所有用户"** → 确定
4. PowerShell 里 `wsl --shutdown` 后重开 WSL
5. 验证：`ncu --set basic --launch-count 1 /tmp/relu.bin` 不再报 ERR 即成功

**第 1 步：用仓库自带的 relu 五连对比当第一课**
`kernels/nvidia-nsight/relu.cu` 是独立程序（无需 torch），5 个 relu 变体差 4 倍，ncu 能告诉你为什么：

```bash
cd ~/workspace/LeetCUDA/kernels/nvidia-nsight
nvcc -arch=sm_89 -O3 --generate-line-info -g relu.cu -o /tmp/relu.bin   # -g+line-info: ncu 里能看源码行
ncu --set full -o /tmp/relu_prof -f /tmp/relu.bin                        # 全量采集(慢, 一次性)
ncu-ui /tmp/relu_prof.ncu-rep                                            # 或 CLI:
ncu --set basic -k "regex:relu" /tmp/relu.bin                            # 快扫
```

看什么（按顺序）：① **SOL 页**的 Memory % ——5 个变体应该都接近带宽上限，但 naive 只有 1/4；
② **Memory Workload Analysis** 的 DRAM Throughput 和 sector 效率——naive 用 fp32 标量读，
事务数是 pack 版（128-bit 向量化）的 4 倍 → 这就是 1.67ms vs 0.41ms 的物证；
③ Source 页配合 `--generate-line-info` 能对应到源码行。
同样方法再来一遍 `elementwise.cu`，ncu 就算正式入门了。
