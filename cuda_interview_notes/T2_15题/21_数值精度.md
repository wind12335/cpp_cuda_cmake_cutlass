# 21 数值精度：fp32 / fp16 / bf16 / tf32 / fp8

## 面试口述版

一张位宽表打天下：**fp32**（1 符号 + 8 指数 + 23 尾数）训练祖传精度；
**fp16**（5 指数 + 10 尾数）范围窄（max ~65504），容易上溢，所以**累加必须 fp32**、
常配 loss scaling；**bf16**（8 指数 + 7 尾数）指数位和 fp32 一样宽——范围大不易溢出、
精度低但训练 tolerable，现代大模型训练默认它，转换可直接截断 fp32；**tf32**（19 位）是
Ampere+ Tensor Core 对 fp32 输入的内部截断，范围同 fp32、精度高于 bf16，CUDA 侧
`cublasSetMathMode(CUBLAS_TF32_TENSOR_OP_MATH)` 一开就生效；**fp8**（e4m3/e5m2 两档）
推理/部分训练前向用，配 per-tensor/per-block scaling。
选型逻辑：**动态范围优先用 bf16，精度优先用 fp16（配 scaling），能掉就掉 fp8/int8 换带宽**。
对 infra 的意义：位宽减半 = 显存减半 = 带宽翻倍 = 通信量减半——量化不只是算法问题，
是你 overlap 课题里"通信量"的第一杠杆。

## 高频追问

- **为什么 fp16 累加要 fp32？** 大数吃小数：fp16 只有 10 位尾数，几万次累加的舍入误差会淹没结果；fp32 累加是所有混合精度框架的标配。
- **bf16 精度差为什么训练没事？** 梯度更新对尾数误差不敏感（随机游走特性），对指数范围敏感（loss scale 就是为 fp16 的窄范围发明的）；bf16 把 scaling 都省了。
- **混合精度训练里哪些必须留 fp32？** master weights、loss、optimizer state（Adam 的 m/v）——fp16/bf16 只做前向/反向的矩阵乘输入。
- **CUDA 侧 API 熟悉吗？** `__half`/`__nv_bfloat16` 类型、`half2` 向量化（联动 04 合并访存）、wmma/mma 的 fp16 进 fp32 累加组合。

## 记忆钩子

"fp16 精而窄要 scaling，bf16 糙而广免操心，tf32 是 fp32 的免费加速，fp8 是带宽的终极换法；累加永远 fp32。"

**人话版**：一句话记四种精度——**fp16**：尾数多（精度高）但指数位少（范围窄，大数会溢出），
训练要配 loss scaling 补救；**bf16**：指数位和 fp32 一样宽（不容易溢出），尾数少（糙）但训练
不在乎，现代大模型默认它，连 scaling 都省了；**tf32**：fp32 输入自动截短喂给 Tensor Core 的
"免费加速"，范围精度都居中；**fp8**：8 位终极压缩，换最大带宽；唯一铁律：**累加一律 fp32**，
否则几万次加法的舍入误差会淹没结果。
