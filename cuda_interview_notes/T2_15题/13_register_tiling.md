# 13 Register Tiling / 每线程多元素（Thread Coarsening）

## 面试口述版

block 级 tiling 之后的下一刀：**每个线程算 C 的一小块（如 8×8）而不是 1 个元素**。
收益有三：① **寄存器复用**——从 shared 读一次 A 的 8 行值、B 的 8 列值，能攒出 64 个乘加，
一次加载喂 64 次 FMA，shared 带宽压力骤降；② **索引计算摊薄**——8×8 个结果共享同一套下标逻辑；
③ **独立累加链**——64 个结果放在 64 个寄存器里各自累加，无数据依赖，FMA 流水线打满
（反过来"一个线程算一列"的累加是串行依赖链，FMA 延迟吃满吞吐）。
代价：**寄存器压力**——64 个累加寄存器 + A/B 暂存，每线程轻松上百寄存器，occupancy 下降（联动 07）。
所以它是"用寄存器换 shared 带宽、换指令效率"的权衡，MMA kernel 里对应的就是
_frag 累加器矩阵（wmma::accumulator 或 mma PTX 的 D 矩阵寄存器组）。

## 高频追问

- **为什么 8×8 这种形状？** 经验起点是 4×4~8×8 平方形状；要和 block tile、warp 数匹配（128×128 block 配 8×8 = 16×16 线程 = 8 warp，正好）。形状越方，A/B 数据复用比越好。
- **怎么判断寄存器溢出了？** ncu 看每线程寄存器数是否 >255 触发 spill（local memory 出现流量）；或编译期 `-Xptxas -v` 打印寄存器用量。
- **和向量化的关系？** 相辅相成：8×8 是空间上的复用，float4 是搬运位宽上的加宽；LeetCUDA 里 `x4` 后缀的 kernel 两招一起用。

## 记忆钩子

"一线程一元素是零工，一线程 8×8 是包工：一次领料，64 件活；代价是口袋（寄存器）要够大。"

**人话版**：让每个线程算 C 的一个 8×8 小块（64 个结果），而不是一个元素。好处：从 shared memory
领一次料（A 的一行片段 + B 的一列片段），能完成 64 次乘加——数据复用率暴涨，且 64 个结果各自
累加、互不依赖，计算流水线不断档。代价：64 个结果加中间量全要住寄存器，寄存器用量暴涨，
可能挤压 occupancy（第 07 题）。
