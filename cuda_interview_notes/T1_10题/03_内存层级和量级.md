# 03 内存层级和量级

## 面试口述版

从快到慢五层，**延迟量级必须张口就来**：
① **Register**（每线程私有）：~1 cycle；每 SM 寄存器堆 ~256KB，这就是"寄存器是稀缺资源"的原因；
② **Shared Memory**（block 内共享，物理上和 L1 共用 ~128KB/SM，可配置划分）：~30 cycles；
③ **L2**（全 GPU 共享，4060 上 32MB 量级）：~200 cycles；
④ **Global/显存**（HBM/GDDR）：~400-600 cycles，带宽才是主战场（4060 Laptop ~272GB/s，HBM3e 的 H100 3.35TB/s）；
⑤ **Host 内存**：走 PCIe（Gen5 x16 ~64GB/s），**跨 PCIe 的传输比显存内访问慢一个数量级以上**——所以"少搬数据、能留卡上就留卡上"是第一戒律。
各层容量的"量级感"直接决定优化决策：tile 大小受 shared 上限约束、每线程寄存器数受 occupancy 约束（联动 07）。

## 高频追问

- **为什么 shared memory 快这么多还只有 ~100KB？** 片上 SRAM 面积/功耗昂贵，是拿容量换速度；所以 tiling 的本质就是"把要复用的数据搬进这块贵而小的 SRAM"。
- **register 溢出（spill）是什么？** 编译器需要的寄存器超过配额，把数据挪到显存（local memory）——性能悬崖，ncu 里看 local memory 指标非零就要警惕。
- **NCCL 语境？** 你论文里通信开销的计算：NVLink ~900GB/s（单向 ~450），PCIe ~64GB/s，IB 400Gb/s≈50GB/s——带宽量级差决定了"通信能不能被计算藏住"。

## 记忆钩子

"1 / 30 / 200 / 500：寄存器、shared、L2、显存；跨 PCIe 再加十倍。容量反过来，越快越少。"

**人话版**：前面四个数字是**访问延迟的 cycle 量级**（读一次数据要等多少拍）：寄存器约 1 拍、
shared memory 约 30 拍、L2 约 200 拍、显存约 500 拍；而从显存搬到主机内存（跨 PCIe）还要再慢
一个数量级。"容量反过来" = 越快的层越小：寄存器每线程几十个、shared 每 SM ~128KB、
L2 几十 MB、显存 8GB——**又快又大不存在**，所有优化本质上都是在"把数据搬到更快的层去复用"。
