# 04 合并访存（Coalescing）

## 面试口述版

显存的最小有效传输单位是 32B/128B 的**内存事务**。一个 warp 的 32 个线程同时访存时，
如果它们的地址**落在连续的 128B 内**，硬件合并成 1-4 个事务一次搬完——这就是合并访存；
如果 32 个线程的地址分散（比如跨步访问、或矩阵按列访问 row-major 数据），就要拆成最多 32 个事务，
**带宽利用率掉 32 倍**。保证合并的三个习惯：① 索引公式让**相邻 threadIdx 对应相邻地址**；
② 矩阵转置这类"读合并、写必散"的场景用 shared memory 做中转（读进 shared 是合并的，
从 shared 拿转置后的数据再写出去也是合并的，联动 05 题）；③ 能用 float4/int4 向量化就向量化
（128-bit 一条指令，事务数再降 4 倍）。

## 高频追问

- **AoS vs SoA？** AoS（结构体数组）里各字段交错存放，warp 访问同一字段时地址跨步 → 不合并；SoA（数组结构体/字段分列）→ 合并。参数布局（weights 布局、NCCL buffer 布局）都吃这条。
- **不合并的访问结果对吗？** 对，只是慢——正确性和性能分开记。
- **L2 帮忙吗？** 部分场景 L2 能吸收一些碎片访问，但别指望，写代码时就按合并设计。
- **怎么用工具确认？** ncu 的 Memory Workload Analysis 看"理想事务数 vs 实际事务数"，差距大就是不合并（联动 25 题）。

## 记忆钩子

"相邻线程拿相邻地址，一条总线全搬走；跨步一散，事务爆炸 32 倍。"

**人话版**：显存搬运按"内存事务"（一次至少 32/128 字节）计费。一个 warp 的 32 个线程如果访问的
地址**连成一片**（线程 0 拿字节 0-3、线程 1 拿字节 4-7……），硬件合并成 1-4 个事务一次拉完；
但如果地址是跳着的（线程 0 拿 0、线程 1 拿 128……），每个线程各自触发事务，最多 32 个——
同样的数据量，搬运次数翻 32 倍，带宽利用率掉 32 倍。
