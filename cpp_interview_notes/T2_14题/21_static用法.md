# 21 static 的全部用法

## 面试口述版

四个位置四种含义，共同点是"延长生命周期/限制可见性"：
① **函数内局部 static**：首次执行到才初始化、程序结束才销毁；C++11 起初始化是线程安全的（"magic statics"），
单例的 Meyers 写法 `static Instance inst; return inst;` 就靠它。
② **类的 static 成员变量**：属于类不属于对象，所有对象共享一份，类内声明、**类外定义**（C++17 可用 inline 变量免类外定义）。
③ **类的 static 成员函数**：没有 this，只能访问静态成员——因为不依赖任何对象实例。
④ **全局/命名空间级 static**：限制链接性为**内部链接**，只在本编译单元可见——C 里防命名冲突的老手艺，
C++ 更推荐匿名命名空间。

## 高频追问

- **static 局部变量的线程安全怎么实现的？** 编译器生成一个守卫标志 + 双重检查（等效双检锁），首次初始化完成前其他线程阻塞等待——这就是为什么 Meyers 单例 C++11 后不用自己加锁。
- **静态初始化顺序惨案（static initialization order fiasco）？** 不同编译单元的全局 static 初始化顺序未定义，若 A.cpp 的全局对象构造用了 B.cpp 的全局对象就可能踩到未初始化的——解法是换成"函数内局部 static"（首次用时才构造）。
- **static 成员何时分配？** 静态存储区，程序启动（或首次动态初始化）就存在，不是堆也不是栈。

## 记忆钩子

"局部 static 是懒汉单例的地基；类内声明类外定义；全局 static 是'只许本文件看'。"

**人话版**：三种 static 各管一摊——
① 函数内局部 static：第一次执行到才初始化、程序结束才销毁，且 C++11 起初始化线程安全——
单例模式就靠它（"懒汉" = 第一次用才创建）；
② 类的 static 成员：属于整个类而不是某个对象，所有实例共享一份；
③ 全局/文件级 static：限制这个变量/函数**只能被本 .cpp 文件看见**，别的文件 extern 也找不到——
防止命名冲突。
