# 26 inline：声明意图、编译器可拒绝、和宏的区别

## 面试口述版

inline 关键字在现代 C++ 里**主要是链接语义，不是性能指令**：
① **解决 ODR（单一定义规则）**——头文件里的函数/变量被多个 .cpp include，链接会重定义冲突；
标了 inline 就是承诺"所有翻译单元里的这个定义完全相同，链接器合并成一份"。
头文件里直接定义的普通函数、C++17 的 inline 变量（全局常量表、单例指针）都靠它。
② **内联展开只是"请求"**：编译器按成本模型自行决定，短小热函数通常展开，大的直接拒绝；
优化级别也影响（-O0 基本不内联）。真正强制内联是编译器扩展（`__attribute__((always_inline))`）。
③ **和宏的区别**：宏是预处理文本替换——无类型检查、有副作用陷阱（`MAX(a++, b)` 自增两次）、不可调试；
inline 函数是真函数：类型安全、参数只求值一次、可断点可单步。

## 高频追问

- **inline 函数一定更快吗？** 不一定：展开失败就是普通调用；展开成功但代码膨胀导致 I-cache 效率下降也可能负优化——和 kernel 里盲目展开循环一个道理。
- **什么时候手动 inline 有意义？** 头文件共享定义（语义必须）+ 极短的热函数（性能顺手）。
- **inline 变量是啥？** C++17 起头文件里 `inline int g_count = 0;` 合法，各 TU 共享一份——单例、全局注册表常用。

## 记忆钩子

"inline 先是链接器的'合并声明'，其次才是优化器的'展开建议'；宏是文本把戏，inline 是真函数。"

**人话版**：inline 关键字的**第一职责**是解决链接问题：头文件里的函数/变量会被多个 .cpp 包含，
每个 .cpp 都有一份定义，链接时就"重定义冲突"——inline 承诺"所有副本完全相同，链接器只留一份"。
**第二职责**才是建议编译器把调用点展开成函数体（可拒绝）。
和宏的区别：宏是预处理阶段的文本替换（`#define MAX(a,b) ...`），没有类型检查、参数有副作用陷阱；
inline 函数是真函数，类型安全、可调试。
