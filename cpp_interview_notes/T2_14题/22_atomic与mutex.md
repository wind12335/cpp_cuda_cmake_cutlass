# 22 atomic 是什么，和 mutex 差在哪

## 面试口述版

`std::atomic<T>` 提供对**单个变量**的无锁原子操作：load/store/exchange、fetch_add 这类
**RMW**（read-modify-write 的缩写，"读-改-写"一条龙——比如自增 = 读出来+1+写回去，普通做法这三步
之间会被别的线程插队，原子版把它合成不可分割的一步），
底层对应 CPU 的原子指令（x86 的 LOCK 前缀、fetch_add 就是 LOCK XADD，CAS 是 LOCK CMPXCHG）。
**CAS**（compare-and-swap，比较并交换）：一把"乐观锁"——"如果变量的值还是我看到的旧值，就换成新值；
否则失败重试"。`compare_exchange_weak/strong` 就是它的接口，无锁队列全靠这个原语搭起来。
**mutex 保护的是"一段临界区"**：可以原子地维护跨多个变量的不变量（比如同时改两个字段保持一致），
代价是竞争时线程挂起/唤醒（系统调用级开销）。
选择原则：**单一计数器/标志位/指针交换 → atomic（快，无锁）；跨多个变量的一致性 → mutex**。
用 atomic 硬凑多变量一致性，只会写出"每步都原子、合起来不原子"的 bug。
CAS（compare_exchange_weak/strong）是原子操作的核心原语，无锁队列就靠它。

## 高频追问

- **atomic<int>++ 和 int++ 差在哪？** int++ 是"读-改-写"三条指令，多线程交错丢更新；atomic++ 是一条原子 RMW（LOCK XADD），不丢。
- **weak 和 strong 的 CAS 差别？** weak 允许伪失败（平台原因白白失败），可放在循环里省一条指令；strong 保证不伪失败。循环里用 weak，单次判断用 strong。
- **atomic 性能代价？** 仍是共享缓存行的争用（要读改写涉及缓存一致性），高竞争下同样是瓶颈——所以有分片计数这类优化。
- **和 GPU 对应？** CUDA 里 atomicAdd 同样语义，但全局内存原子吞吐低，高竞争同样要分桶/归约规避——思想完全同构。

## 记忆钩子

"atomic 管一个数的原子性，mutex 管一段逻辑的一致性；一个变两步丢，两个变锁一起。"

**人话版**：atomic 保证**单个变量**的一次操作不可分割（自增不会被人插队拆成"读、加、写"三段）；
mutex 保证**一段代码**执行期间别人进不来（可以同时维护多个变量之间的关系）。
"一个变两步丢"：裸 int++ 是三步操作，线程交错执行就会互相覆盖丢更新；
"两个变锁一起"：两个各自原子的变量，合起来的一致性必须靠 mutex 保护——atomic 管不了组合逻辑。
