# 05 shared_ptr 线程安全吗

## 面试口述版

要分三层说，混着说就错了：
1. **引用计数是原子的** —— 不同线程各自持有"同一个对象的不同的 shared_ptr 拷贝"，随便拷贝、析构，计数加减都安全；
2. **被管理的对象 T 本身不受到任何保护** —— 两个线程各持一份拷贝、同时读写 *p，照样数据竞争，shared_ptr 不背这个锅；
3. **同一个 shared_ptr 实例本身被多线程读写不安全** —— 线程 A `p = make_shared<...>()` 的同时线程 B 拷贝 p，对 p（两个指针成员）的并发读写是数据竞争，未定义行为，要用 mutex 或 C++20 的 `std::atomic<std::shared_ptr<T>>`。
一句话总结：**计数原子 ≠ 对象安全 ≠ 指针本身安全**。

## 高频追问

- **多线程读同一个 shared_ptr 实例、只读不写？** 安全（并发只读永远安全）。
- **那对象的数据竞争怎么解决？** 照常上 mutex，或对象内部自己保证（比如 NCCL 通信句柄这类，通常外面包一层带锁的 manager）。
- **weak_ptr 并发访问呢？** weak_ptr::lock 是原子的、安全，这是它存在的意义之一。

## 记忆钩子

"账本原子、货没人看、本子别共写。"

**人话版**：三层安全性，对应三种情况：
① **账本原子** = 引用计数的加减是原子操作 → 不同线程各自持有"同一对象的不同的 shared_ptr 拷贝"，
随便拷贝析构，安全；
② **货没人看** = shared_ptr 只管数数，不管对象里面的数据 → 两个线程同时读写 `p->value` 照样是
数据竞争，对象要自己上锁；
③ **本子别共写** = 多个线程对**同一个 shared_ptr 变量**同时赋值/拷贝 → 这才是未定义行为
（shared_ptr 变量本身被并发读写），解法：mutex 或 C++20 的 `std::atomic<std::shared_ptr<T>>`。
