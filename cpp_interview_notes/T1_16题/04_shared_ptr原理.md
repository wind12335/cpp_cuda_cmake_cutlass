# 04 shared_ptr 实现原理

## 先把五个名词钉死（配内存图，别跳过）

shared_ptr **本身是一个类对象**，不是魔法——它在内存里就是**两根指针，16 字节**（x64）：

```
   栈上（你的函数里）                 堆上
  ┌──────────────────┐
  │ shared_ptr sp     │
  │  p ────────────────────→ ┌─────────────┐
  │  cb ───────────────┐     │ Res 对象     │ ← 你 new 出来的那个
  └──────────────────┘  │    └─────────────┘
                        │    ┌─────────────┐
  ┌──────────────────┐  └──→ │ 控制块(账本)  │ ← shared_ptr 创建时 new 出来的
  │ shared_ptr b(拷贝)│      │  strong = 2 │ ← 强引用计数: 几个 shared_ptr 在"拥有"
  │  p ───────────────│────→ │  weak   = 1 │ ← 弱引用计数: 几个 weak_ptr 在"观察"
  │  cb ──────────────│────→ │  deleter    │ ← "怎么销毁对象"的函数(默认 delete)
  └──────────────────┘      └─────────────┘   (allocator: "账本内存怎么分配", 默认 new)
```

**五个名词，一个一个说**：

1. **裸指针 `T*`**：指向你 new 的对象，就是普通指针，shared_ptr 借它帮你用对象。
2. **控制块（控制块 = 上面那个"账本"结构体）**：在堆上的一个小结构体，装着计数器和删除器。
   拷贝 shared_ptr 不复制对象、也不复制账本——只是两根指针抄一份、账本计数 +1。
3. **强引用计数 ≠ weak_ptr**！计数是账本里的**一个数字**，weak_ptr 是**一个观察者对象**。
   关系是：每存在一个 weak_ptr 观察这个对象，账本里的弱计数就 +1。分工：
   强计数 → 0：**对象**销毁；强、弱都 → 0：**账本**也销毁（观察者还要靠账本查"对象死了没"）。
4. **deleter（删除器）**：账本里存的"**怎么销毁这个对象**"的函数。默认是 `delete p`；
   可以换成别的：管文件传 `fclose`、管 GPU 显存传 `cudaFree`、管 malloc 的内存传 `free`。
   它存在账本里，所以无论哪一份 shared_ptr 拷贝最后销毁对象，用的都是同一个销毁方式。
5. **allocator（分配器）**：账本那块内存"用什么方式分配"的策略，默认 new。
   99% 的代码一辈子不改它——**知道有这个东西即可**，面试能说出"它是控制块内存的分配策略"就够了。

## 面试口述版（60-90 秒）

shared_ptr = 一个裸指针 T* + 一个指向**堆上控制块**的指针，两次 new、对象本身不含计数。
控制块里至少有：**强引用计数、弱引用计数**（还有删除器和分配器）。
拷贝 shared_ptr 时强计数 +1（原子操作），析构时 -1，减到 0 就用删除器销毁被管对象；
强计数归零后对象销毁，等弱计数也归零，控制块自身才释放（weak_ptr 还要靠它判断对象死没死）。
所以 shared_ptr 的开销是：对象外多一块控制块内存 + 拷贝/析构时的原子加减。

## 高频追问

- **控制块里具体有什么？** strong count、weak count、deleter（决定"记不记得实际类型"，
  这就是 02 题里 shared_ptr 不需要虚析构的原因——删除器记住了创建时的真实类型）、allocator。
- **引用计数是原子的吗？** 是（++/-- 都原子），所以"不同线程各持一份 shared_ptr 拷贝"是安全的；
  但"多个线程写同一个 shared_ptr 对象本身"不是——下一题。
- **为什么计数不放对象里，要单独一个控制块？** 分离设计让 shared_ptr 能管任意来源的指针
  （malloc 的、第三方返回的），对象类型完全不被侵入。
- **手写一个简版？** 看配套代码——面试手撕高频题，务必写过一遍。

## 新手七问（第一次读代码的常见卡点）

**Q1：`std::atomic<long>` 是什么？和数组有什么不同？**
atomic 是一个"包装类"：把一个普通 long 包起来，让它的一切操作变成**不可分割**。
长得像数组只是因为都用了模板尖括号语法，它**不是容器**，里面只包着一个数字。
为什么需要：普通 long 自增在 CPU 层是"读→加→写回"三步，两线程交错会互相覆盖（丢更新）；
atomic 把三步合成一条不可打断的 CPU 指令。它自带四个常用成员函数：
`.load()` 原子读、`.store(v)` 原子写、`.fetch_add(1)` 原子加 1 并返回**旧值**、
`.fetch_sub(1)` 原子减 1 并返回**旧值**——全是标准库自带，不用我们实现（详见 T2 第 22 题）。

**Q2：`explicit CtrlBlock(...)` 是构造函数吗？explicit 干嘛的？**
是构造函数——**struct 和 class 一样可以有构造函数**。explicit 禁止"从 T* 隐式转换出一个
CtrlBlock"这种意外（第 27 题的规则），纯防御性写法。

**Q3：MyWeakPtr 里那两行成员变量，默认是 private 吗？**
是。**class 的成员默认 private，struct 的成员默认 public**——这是两者唯一的语法区别。
所以 MyWeakPtr 里 `T* p_` 和 `cb_` 不写访问修饰符就是私有的，外部只能走公有函数。
（CtrlBlock 用 struct 就是为了让两个类直接访问账本内部。）

**Q4：`.load()` 是什么？**
atomic 的"原子读"成员函数：安全地读出当前值。atomic 家族里 load=读、store=写、
fetch_add/fetch_sub=原子加减。读计数时用它而不是直接当普通变量用，语义清晰且可控。

**Q5：lock() 到底在什么时候加什么计数？use_weak/weak_count 又是干嘛的？**
两个动作发生在**不同时刻**，别混：
① **构造观察者时**（`MyWeakPtr w = a;`）：弱计数 +1，强计数不动——"观察不拥有"；
② **lock() 调用时**（某天你真想用对象了）：对象活着 → 强计数 +1、换发一个临时 shared_ptr
给你（用完自动 -1）；对象死了 → 返回空。所以对 weak_ptr 一生而言 strong 的**净**变化是 0。
`weak_count()` 是调试查询函数，返回**弱计数的数字**（有几个观察者），不是返回控制块。

**Q6：三个构造函数各在什么时候被调？fetch_add 是谁实现的？**
① `explicit MySharedPtr(T* p, deleter=默认)`：主构造——你 new 好对象交给它，创建账本、强=1
（`=` 默认参数：不传删除器就用默认的）；
② `MySharedPtr(T* p, CtrlBlock* cb)`：**只给 weak_ptr::lock() 用**——lock 已把强计数加好，
这个构造只抄指针、绝不能再加一次；
③ `MySharedPtr(const MySharedPtr& o)`：拷贝构造——"承接"已有对象（`b = a`、按值传参时），
抄两根指针 + 强计数 +1。
`fetch_add(1)` 是 **std::atomic 自带的**标准库成员函数（底层一条 LOCK XADD 指令），不是我们写的。

**Q7：析构里两个"删"有什么区别？**
删的是**两个不同的东西**（当初也是两次 new 的）：`cb_->del(cb_->ptr)` 删的是**管理的对象**
（走删除器，触发 Res 的析构）；`delete cb_` 删的是**账本本身**（控制块结构体）。
分两步的原因：对象死后 weak_ptr 还要靠账本查"对象死了没"，所以对象死 → 账本留；
弱计数也归零 → 账本才删。`fetch_sub(1) == 1` 的判据：返回的是**减之前的旧值**，旧值是 1
说明减完归 0，即"我是最后一个拥有者"。

## 代码 ↔ 概念对照表（04_shared_ptr_impl.cpp）

| md 里的名词 | 手搓代码里的实体 |
|------------|----------------|
| "一个裸指针 T*" | `MySharedPtr` 的成员 `p_` |
| "指向堆上控制块的指针" | `MySharedPtr` 的成员 `cb_` |
| "堆上控制块" | 整个 `struct CtrlBlock`（`new` 出来的账本） |
| 强引用计数 | `CtrlBlock::strong`（`atomic<long>`） |
| 弱引用计数 | `CtrlBlock::weak`（`atomic<long>`）——注意它是**数字**，不是 weak_ptr |
| weak_ptr | `class MyWeakPtr`（观察者：只加弱计数，`lock()` 活着换 shared、死了给空） |
| deleter（删除器） | `CtrlBlock::del` 函数指针（剧情 3 里演示了自定义版接管默认 delete） |
| allocator | **教学版省略**——它只是"账本内存用什么方式分配"的策略，默认 new |

**对照表的读法**：读完 md 回代码里找每个名词的实体；读完代码回 md 里看这句话在讲哪两根指针。
五幕剧情分别演示：创建/拷贝（强计数变化）→ weak 观察（弱计数变、强计数不动）→ 最后拥有者消失
（对象死、账本留）→ 死后 lock() 给空 → 最后观察者离开（账本才销毁）。

## 记忆钩子

"两根指针一根管对象一根管账本；账本在堆上，加减都原子，清零拆对象，人走完拆账本。"

**人话版**：一个 shared_ptr 内部是两根指针：一根指向它管理的对象，另一根指向"账本"
（术语叫**控制块**——堆上一小块记录"现在有几个 shared_ptr 在用这个对象"的计数器）。
拷贝 shared_ptr → 账本 +1；析构 → 账本 -1；**加减都是原子操作**（多线程同时加减也不会算错数，
详见 C++ 22 题）。账本减到 0 → 释放对象；等所有 weak_ptr 也不观察了 → 连账本一起释放。
