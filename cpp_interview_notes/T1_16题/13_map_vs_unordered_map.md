# 13 map vs unordered_map

## 面试口述版

底层和性质完全不同。`std::map` 是**红黑树**：有序（中序遍历按 key 升序）、增删查 O(log n)、
迭代器稳定（除被删元素外从不失效）、空间每节点三指针+颜色位。
`std::unordered_map` 是**哈希表（链地址法）**：平均 O(1)、最坏 O(n)（全碰撞）、无序、
**rehash 时全部迭代器失效**（引用不失效）、有负载因子概念（默认 max_load_factor=1，超了就 rehash 扩桶）。
选择标准：要有序遍历/范围查询/按序统计 → map；纯按键点查、要极致速度 → unordered_map（给自定义 key 记得配好 hash + ==）。

## 高频追问

- **红黑树为什么不用 AVL？** 红黑树牺牲一点平衡性换更少的旋转，增删综合性能更好；面试能说出"近似平衡、最长路径≤最短两倍"即可。
- **哈希冲突怎么处理？** libstdc++ 用链地址法（桶 + 链表）；开放寻址是另一种思路。
- **rehash 过程？** 桶数组扩容（约两倍）→ 所有元素按新桶重排（重新哈希）→ 迭代器全失效。
- **你们 infra 场景怎么选？** 我在参数索引这种"构建期插入、查询期只读"的场景用 unordered_map，构建完不再改，没有 rehash 烦恼。

## 记忆钩子

"map 是排序书架，unordered 是散装抽屉；抽屉快但翻新（rehash）时书签全废。"

**人话版**：map 底层是红黑树（一种保持有序的树结构）——像按编号排列的书架，找书要对半折（O(log n)）
但随时能按顺序浏览；unordered_map 底层是哈希表——像贴了标签的抽屉，按标签一步到位（平均 O(1)）。
"翻新" = **rehash**：哈希表装太满时会扩容并把所有元素重新分配到新抽屉——这一刻你手里所有的
迭代器（"书签"）全部作废，接着用就是未定义行为。
