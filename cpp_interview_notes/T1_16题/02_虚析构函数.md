# 02 为什么基类析构函数要 virtual

## 面试口述版

当用**基类指针 delete 一个派生类对象**时，如果基类析构不是虚函数，
delete 按静态类型只调用基类析构，派生类部分（及其成员、持有的资源）不会被析构 ——
这是未定义行为，典型表现就是内存/资源泄漏。
把基类析构声明为 virtual 后，delete 走虚表找到派生类析构，先析构派生类部分再析构基类部分，完整回收。
规则：**只要一个类会被多态地使用（有其他虚函数、会被基类指针管理），析构就必须是 virtual**。

## 高频追问

- **多态只用引用不用指针还需要吗？** delete 才出问题；只通过引用用、从不 delete 基类指针可以不虚，但没人这么保证，默认写上最安全。
- **std::shared_ptr<Base> p = make_shared<Derived>() 要虚析构吗？** shared_ptr 记住了创建时的实际类型（控制块里存了删除器），即使基类析构不虚也能正确析构 —— 这是它比裸指针/unique_ptr 宽容的地方；unique_ptr<Base> 则必须虚析构。
- **接口类怎么写析构？** `virtual ~Interface() = default;`
- **性能顾虑？** 虚析构只在 delete 那一次调用，热路径无影响。

## 记忆钩子

"delete 谁的指针只看静态类型；不虚就只拆一层，下面全漏。"

**人话版**：两个术语先翻译——**静态类型** = 指针变量声明时的类型（`Base* p` 里的 `Base*`）；
**动态类型** = 它当前实际指向的对象类型（可能是个 Derived）。
`delete p` 时编译器**只看静态类型**（`Base*` → 只调 Base 的析构），完全不管 p 实际指向什么。
析构不是虚的 → 只执行 Base 的析构 = 只拆了"外层一层"，Derived 自己新增的部分
（它 new 出来的内存、打开的文件）永远没人释放 = 泄漏。
析构是虚的 → 先调 Derived 的析构、它结束时自动接着调 Base 的析构，从里到外全拆干净。
