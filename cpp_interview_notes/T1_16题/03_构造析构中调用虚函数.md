# 03 构造/析构函数里调用虚函数会怎样

## 面试口述版

调用的是**当前正在构造/析构的那一层类**的版本，而不是最终派生类的版本，也不会报错（所以容易被忽略）。
原因在 vptr 的赋值时机：进入 Base 构造函数时，vptr 先被设为 Base 的 vtable，
再进入 Derived 构造函数时才改指 Derived 的表；析构则相反，先降级回本层。
所以构造期间对象"是"一个 Base，虚分发只能到 Base 的实现。
更危险的变体：如果该虚函数是纯虚函数且没有本层实现，直接链接/纯虚调用崩溃。

## 高频追问

- **为什么不等构造完再设 vptr？** 构造过程中可能同样有多态需求（每层初始化自己的虚成员），编译器选择"逐层降级/升级"，简单且可预测。
- **实际工程怎么绕开？** 想要"构造时调用派生类初始化逻辑"，用两段式初始化（init() 虚函数在构造完成后调）、工厂函数内部先 new 再调 init，或 CRTP 静态多态。
- **CUDA 语境**：kernel launch 的 host 端封装类如果在基类构造里调虚的 get_stream()，拿到的只会是基类实现 —— 我在自己写 wrapper 类时踩过这类坑。

## 记忆钩子

"构造时我是个 Base，析构时我先变回 Base；虚表跟着构造进度走。"

**人话版**：对象不是一瞬间诞生的，而是**从基类开始一层层往上盖**（先 Base 构造完，再 Derived 构造）；
虚表指针在每层构造开始时被设置成"当前这一层"的表。
所以在 Base 的构造函数里调虚函数时，Derived 的部分**还不存在**，只能调到 Base 自己的版本。
析构方向相反：先拆 Derived、后拆 Base，轮到 Base 析构时派生类部分已经没了——虚调用同样只会落到 Base 的版本。
一句话：**虚调用永远只到"构造/析构已经完成的那一层"为止**。
