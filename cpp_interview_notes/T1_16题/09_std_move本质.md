# 09 std::move 干了什么

## 面试口述版

`std::move` **本身一个字节都不搬**：它就是一个到右值引用的强转 `static_cast<T&&>(t)`，
唯一作用是给编译器一个标记——"这个对象允许被掠夺资源"。
真正干活的是随后的**移动构造/移动赋值**：比如对 std::string 移动，只把内部的数据指针、长度、容量三个字段
从源对象"接管"过来（O(1)），源对象变成有效但未定义的状态（通常是空，但标准不承诺，别对它有内容假设）。
对比拷贝要按元素/按字节复制整个资源（O(n)），移动把"复制资源"变成"换指针"——
这是 C++11 之后 vector 扩容、算法、智能指针全线提速的根本原因。

## 高频追问

- **对 const 对象 move 会怎样？** 静默退化成拷贝（`const T&&` 匹配不上移动构造，回落到拷贝构造）——经典坑。
- **move 之后还能用源对象吗？** 能，但只能赋新值或销毁；读它的值是无定义的（"valid but unspecified"）。
- **move 一个 int/basic 类型？** 没有任何意义，等同拷贝。
- **返回局部变量要写 return std::move(x) 吗？** **不要**！反而抑制 RVO，多出一次移动（见 18 题）。

## 记忆钩子

"move 只是贴标签，搬家的是移动构造；const 对象贴了也白贴。"

**人话版**：`std::move(x)` 自己一个字节都不搬，它只是把 x 标记成"可以抢劫"（编译器据此选择
移动构造而不是拷贝构造）；真正搬资源的是**移动构造函数**——只把源对象的内部指针抢过来，O(1)。
对 const 对象 move：const 的意思是"不许改"，而移动要抢走内部指针（就是改），所以编译器静默退回
拷贝构造——标签白贴了。
