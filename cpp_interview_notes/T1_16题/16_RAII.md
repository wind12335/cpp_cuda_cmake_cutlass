# 16 RAII 是什么

## 面试口述版

RAII = Resource Acquisition Is Initialization，资源获取即初始化：
**把资源的生命周期绑定到对象的生命周期**——构造函数里拿资源（锁、文件、显存句柄），析构函数里放资源。
只要对象在栈上/作为成员，作用域结束、哪怕中途 return、哪怕抛异常展开栈，析构都保证执行，
资源就保证释放。于是"释放代码写在每个出口"的手工管理必然漏（人总会漏一个分支），
RAII 一次写对处处安全。标准库全是 RAII：智能指针、lock_guard/unique_lock、fstream、
jthread；工程里 CUDA 资源同样该 RAII——拿 cudaMalloc/析构 cudaFree、拿 stream/析构 streamDestroy，
异常路径才不会把显存漏成碎片。

## 高频追问

- **和 try/finally（其他语言）比好在哪？** finally 是"每个使用点都要记得写"，RAII 是"资源类写一次，使用点零心智负担"；且 RAII 能管"成员对象的组合资源"，finally 表达不了。
- **异常展开时析构会跑吗？** 会，栈展开逐层调析构（析构里不要再抛异常——析构默认 noexcept，抛了就 terminate）。
- **RAII 对象放堆上没人管不就白搭？** 所以配合智能指针：堆上资源也交给对象管理，形成闭环。

## 代码

见 `16_raii.cpp`：手写锁 guard 和 CUDA 风格的"设备缓冲"guard，演示异常路径下资源依然释放。

```bash
g++ -std=c++17 -pthread 16_raii.cpp -o t16 && ./t16
```

## 记忆钩子

"拿到即初始化，活到即释放；return、异常、跳转，析构永远在场。"

**人话版**：RAII 的操作法 = 把"申请资源"写在构造函数里、"释放资源"写在析构函数里，
然后把资源装进一个**栈上的对象**。因为 C++ 保证：栈上对象只要离开作用域——不管是正常走完、
提前 return、还是半路抛异常——析构函数**百分之百会被执行**，所以资源百分之百被释放。
你不再需要"记得在某个分支里 free/unlock"——忘不掉的东西才是安全的东西。
